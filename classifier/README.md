# classifier: 장학금 공지 분류·추출

크롤러가 만든 `data/raw/{bidx}.json`을 읽어 모집 공지인지 가리고, 금액·마감·조건·서류를 뽑아 `data/extracted/{bidx}.json`에 쓴다.
빌드하면 사람 검수값(`data/reviewed/`)을 덮어써서 화면용 `web/public/scholarships.json`을 만든다.

- 담당: 분류 담당 (이 폴더와 `data/extracted/`는 분류 담당만 고친다)
- 입력 형식: [`data/raw/_sample.json`](../data/raw/_sample.json), 설명은 [`crawler/README.md`](../crawler/README.md)
- 출력 형식: [`data/scholarships.sample.json`](../data/scholarships.sample.json). 필드를 바꾸면 샘플과 이 문서를 같이 고치고 화면 담당에게 알린다.

## 실행

저장소 루트에서 실행한다. 표준 라이브러리만 쓰고, 네트워크·LLM은 쓰지 않는다.

```bash
uv run python classifier/extract.py   # data/raw → data/extracted
uv run python classifier/build.py     # data/extracted + data/reviewed → web/public/scholarships.json
```

| 파일 | 역할 |
|---|---|
| `config.py` | 경로, 분류 규칙에 쓰는 키워드 목록 (규칙을 고칠 때 먼저 여기를 본다) |
| `rules.py` | 제목·본문 → 값 + 근거 문장. 순수 함수만 있다 |
| `dictionary.py` | 학과·단과대·계열 이름, 시·도 이름, 지역으로 오인하는 말("동시", "연구") 목록 |
| `extract.py` | raw 1건 → extracted 1건 저장 |
| `build.py` | extracted + reviewed 합치기, '모집'만 남겨 scholarships.json 저장 |

## 처리 순서

1. **공지 종류** (제목만 본다): 결과 단어("지급완료", "심사 결과"…) → `결과`, 안내 단어("서약서", "박람회"…) → `안내`, 모집 단어 + 장학 단어 → `모집`, 나머지 → `확인필요`. **빌드에는 `모집`만 들어간다.**
2. **유형**: 근로장학 게시판(`bnum=57138`)이거나 제목에 "근로" → `근로`, "(홍보)"·"재단"·"장학회" → `교외`, 나머지 → `교내`.
3. **금액**: 금액 단어가 있는 줄에서 등록금 비율 → 시급 → 만원 → 원 순서로 찾는다. 같은 줄에서 소득 단어("차상위", "소득")보다 뒤에 나오는 금액은 소득 기준일 수 있어 쓰지 않는다. "또는", "택1"이 있으면 값은 첫 금액, `text`는 줄 전체로 둔다.
4. **마감일**: 제목의 `~11/12`을 먼저 보고(연장되면 제목이 바뀌므로), 없으면 본문의 "신청기간", "까지" 줄에서 마지막 날짜를 쓴다. 발표·면접·근무기간 줄은 건너뛴다. "선발 완료시까지" 같은 상시 모집은 `deadline: null`, `deadline_text: "상시 모집 (…)"`로 두고 확인 필요로 표시하지 않는다.
5. **조건**: 학년, 최소 평점(`gpa_min`, 4.5 만점), 최소 점수(`score_min`, 100점 만점), 소득 구간 상한. "우대", "가산점" 줄은 조건이 아니라서 뺀다. 소득 언급만 있고 값을 못 뽑으면 `eligibility.unclear`에 넣는다.
6. **학과·거주지**: 아래 "학과·거주지 규칙" 참고.
7. **그 외 조건 (문장형)**: 아래 "그 외 조건" 참고.
8. **준비 부담**: "제출서류" 다음 목록 중 서류 이름처럼 보이는 것만 남긴다. 본문에 "면접"이 있으면 면접 있음.
9. **근거 문장**: 금액·마감·중복 제한·학과·거주지는 값을 뽑은 원문 줄을 `evidence`에 남긴다. 규칙은 원문에 있는 글자만 뽑으므로 숫자를 지어내지 않는다.

못 찾은 값은 `null`로 두고 `needs_check`에 이름을 넣는다. 그 값은 검수에서 채운다.

## 학과·거주지 규칙

이름 찾기는 쉽고, 어려운 건 **그 이름이 자격 조건인지** 판단하는 것이다. 그래서 두 단계로 한다.

1. **이름 찾기**
   - 학과: `dictionary.py`의 학과·단과대·계열 이름. 긴 이름부터 찾아서 "벤처경영학과" 안의 "경영학과"는 따로 잡지 않는다. "대상, 자격, 재학생, 전공자" 같은 말이 있는 줄에서만 찾는다.
   - 거주지: 시·도 목록과 `○○시/군/구` 패턴. "거주, 주민등록, 출신, 구민" 같은 말이 있는 줄에서 찾는다. "서울과학기술대학교"의 "서울"처럼 뒤에 다른 글자가 붙은 것은 지역으로 보지 않는다.
   - 본문에서 못 찾으면 제목을 본다. "은평구민", "거창군 지역출신"은 확실한 조건, "통영시 저소득 대학생 장학금"처럼 이름만 있으면 값은 넣되 `unclear`에 넣는다.
2. **이름 앞뒤를 보고 거르기** (`config.py`의 단어 목록)

| 경우 | 보는 곳 | 예 | 결과 |
|---|---|---|---|
| 우대·문의·위치 문맥 (`NOT_CONDITION_WORDS`) | 이름 앞 25자, 뒤 12자 | "학교인근 거주자 **우대**", "**관련학과**: 화공생명공학과", "**문의**: 전기정보공학과 사무실", "서울 **소재** 대학", "**신청방법**: 방문**접수** (서울특별시 은평구 …)" | 거름 |
| 앞 줄에 이어 쓴 설명 (`CONTINUATION_MARKS`) | 줄이 `※`, `-`로 시작하면 앞 줄 | "우대사항: 아래 학과" 다음 줄 "- 컴퓨터공학과 재학생" | 거름 |
| 제한 없음 (`NO_LIMIT_WORDS`) | 뒤 12자 | "거주지 **무관**" | 거름 |
| 제외 조건 (`EXCLUDE_AFTER_WORDS`) | 뒤 12자 | "건축학전공 **제외**" | 거르고 `unclear`에 넣음 (제외 조건은 아직 필드가 없음) |

- 거른 것은 `data/extracted/{bidx}.json`의 `filtered_conditions`에 이유와 함께 남는다. 검수할 때 잘못 거른 게 없는지 여기서 본다.
- 단과대("공과대학")나 계열("공학계열")은 어느 학과까지인지 공지마다 달라서 값은 넣고 `unclear`에 넣는다.
- 거주지가 여러 곳이면 `"은평구, 서울특별시"`처럼 쉼표로 잇는다.

## 그 외 조건 (`eligibility.other_conditions`)

"학칙에 의한 징계사실이 없는 자", "북한이탈청소년", "경제적 사유로 학업에 어려움이 있는 학생"처럼 **값으로 바꿀 수 없는 조건**은 해석하지 않고 원문 문장을 목록으로 따로 담는다. 화면에서는 필터에 쓰지 않고 카드에 읽기용으로 보여 준다.

1. "지원자격", "선발대상", "자격조건", "제외 대상" 같은 문단 제목 줄을 찾는다. 콜론이 없는 30자 넘는 안내 문장은 제목으로 보지 않는다.
2. 제목 아래 줄을 번호 단계(`1.` > `가.` > `○·-·※` > 번호 없음)로 보고, 같거나 높은 단계가 나오면 문단이 끝난 것으로 본다. 최대 10줄.
3. 쉼표로 끝난 줄은 다음 줄과 합친다.
4. 빼는 줄
   - 우대·가산·순위·우선·관련학과 줄과, 그 줄에 번호 없이 이어 쓴 줄 (`CONDITION_SKIP_WORDS`)
   - 문단 제목만 있는 줄 ("4. (재단)지원자격")
   - 신청 방법·서류 안내 줄 ("제출서류", "신청 시", "참고", "첨부" …, `CONDITION_NOT_WORDS`)과 "09:00", "11.10(화)" 같은 일정 줄
   - 학년·평점·점수·소득처럼 이미 값으로 뽑는 조건만 있는 줄 ("본교 재학생 2~4학년, 성적 3.0 이상")
5. "제외 대상 : …"은 `"제외: …"`로 적는다. 문장은 100자, 목록은 8개까지.

앞뒤 몇 글자를 보고 조건을 더 잘게 거르는 규칙(면접 부정어, 학년·성적의 우대·순위, 금액의 총예산·작년)은 **보류 중이다 (2026-11-13)**. 지금은 줄 단위로만 거른다.

## 추출 결과 필드 (`data/extracted/{bidx}.json`)

`data/scholarships.sample.json`의 항목 하나와 같고, 아래 필드가 더 있다. 아래 필드는 빌드할 때 빠진다.

| 필드 | 설명 |
|---|---|
| `notice_kind` | `모집` / `결과` / `안내` / `확인필요` |
| `notice_kind_reason` | 그렇게 판단한 이유 (예: "제목에 '지급완료'") |
| `content_hash` | 원본의 해시. 원본이 바뀌었는지 비교할 때 쓴다 |
| `filtered_conditions` | 학과·지역 이름이 나왔지만 조건이 아니라고 보고 거른 것. `{field, text, reason, line}` |

화면까지 가는 필드 중 샘플에 새로 넣은 것:

| 필드 | 설명 |
|---|---|
| `closed` | 제목에 "(마감)", "선발완료" 등이 있으면 `true`. 마감일을 모르는 공지도 모집이 끝났는지 알 수 있다 |
| `needs_check` | 사람이 확인해야 하는 항목: `amount`, `deadline`, `documents`, `poster_only`(본문 없이 포스터만), `body_short`(본문 100자 미만) |
| `eligibility.score_min` | 100점 만점 성적 하한 (예: "백분율 85점 이상", "C0(70점) 이상"). 4.5 만점 평점은 `gpa_min` |
| `eligibility.other_conditions` | 값으로 못 바꾸는 조건 문장 목록 (읽기용, 필터에 쓰지 않음) |
| `evidence.departments`, `evidence.residence` | 학과·거주지 값을 뽑은 원문 줄 (제목에서 뽑았으면 제목) |

## 검수 (`data/reviewed/{bidx}.json`)

틀린 값만 적는다. 안쪽 필드는 그 필드만 덮어쓴다.

```json
{
  "_comment": "포스터 보고 입력",
  "amount": { "type": "lump_sum", "value": 3000000, "text": "300만원" },
  "deadline": "2026-11-20"
}
```

- 모집이 아닌데 `모집`으로 분류됐으면 `{"exclude": true}`
- 모집인데 다른 종류로 분류됐으면 `{"notice_kind": "모집"}`
- 검수 파일이 있는 항목은 빌드 결과에 `reviewed: true`가 붙는다.

## 첫 실행 결과 (본부 장학공지 37건, 2026-11-13)

- 모집 27, 결과 3, 안내 5, 확인필요 2 (시험지원인력 모집, KRA 아동돌봄. 장학금인지 사람이 판단)
- 모집 27건 중 금액을 뽑은 것 9건, 마감일(날짜 18건 + 상시 모집 2건)을 뽑은 것 20건, 100점 만점 성적 조건 7건.
- 못 뽑은 것의 대부분은 본문이 거의 없는 교외 "(홍보)" 공지(포스터만 13건)이고, 첨부 텍스트는 아직 0건이다. 포스터나 첨부를 보고 검수에서 채워야 한다.
- 알려진 한계: 금액이 여러 개면 첫 금액만 `value`에 들어간다. 요약은 본문 한 줄을 자른 것이라 어색할 수 있다.
- 학과·거주지: 학과 조건 1건(895588 "공학계열", 확인 필요), 거주지 6건(은평구·거창군은 확실, 논산시·강화군·통영시는 제목에서만 나와 확인 필요). 897664 "학교인근 거주자 우대", 897699 "관련학과(우대사항)", 896404 접수처 주소를 조건에서 걸렀다.
- 그 외 조건: 모집 27건 중 10건에서 조건 문장을 뽑았다. 897471의 "우대 사항:" 아래 목록은 걸렀다. 896404처럼 한 문장이 여러 줄로 나뉜 공지는 문장이 끊겨 보일 수 있고, 896900처럼 대상별 조건이 여러 번 나오면 비슷한 문장이 반복된다.
