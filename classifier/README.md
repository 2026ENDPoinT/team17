# classifier: 장학금 공지 분류·추출

크롤러가 만든 `data/raw/{bidx}.json`을 읽어 공지마다 금액·마감·조건·서류를 뽑고 **라벨(모집 / 수정 / 완료)**을 붙여 `data/extracted/{bidx}.json`에 쓴다.
전체 단계는 **수집 → 라벨링(이 폴더) → 이벤트 묶기 → 화면**이다 ([docs/scholarship-mvp.md](../docs/scholarship-mvp.md) 3절). 이벤트 묶기 단계가 `data/extracted/`를 읽어 같은 장학금의 공지들을 이벤트 1개로 묶는다.
`build.py`(공지 단위 `scholarships.json`)는 이벤트 묶기 이전 방식이다. 최종 빌드 담당이 정해질 때까지 남겨 둔다.

- 담당: 분류 담당 (이 폴더와 `data/extracted/`는 분류 담당만 고친다)
- 입력 형식: [`data/raw/_sample.json`](../data/raw/_sample.json), 설명은 [`crawler/README.md`](../crawler/README.md)
- 출력 형식: [`data/scholarships.sample.json`](../data/scholarships.sample.json). 필드를 바꾸면 샘플과 이 문서를 같이 고치고 화면 담당에게 알린다.

## 실행

저장소 루트에서 실행한다. 표준 라이브러리만 쓰고, 네트워크·LLM은 쓰지 않는다.

```bash
uv run python classifier/extract.py   # data/raw → data/extracted
uv run python classifier/extract.py --raw data/raw_test --out <저장소 밖 폴더>  # 6개월 시험 데이터로 규칙 점검 (data/extracted에 쓰지 않는다)
uv run python classifier/build.py     # data/extracted + data/reviewed → web/public/scholarships.json
uv run python classifier/check_rules.py  # 규칙 정답 세트 (맞힌 수 출력)
```

| 파일 | 역할 |
|---|---|
| `config.py` | 경로, 분류 규칙에 쓰는 키워드 목록 (규칙을 고칠 때 먼저 여기를 본다) |
| `parser.py` | **구문 분석**: 텍스트 → 문단 트리 (자격·금액·기간·서류·우대·일정·방법) |
| `rules.py` | **어휘 분석·의미 분석**: 문단 텍스트 → 값 + 근거 문장. 순수 함수만 있다 |
| `dictionary.py` | 심볼 테이블: 학과·단과대·계열 이름, 시·도 이름, 지역으로 오인하는 말("동시", "연구") |
| `extract.py` | 단계 연결: raw 1건 → 문단 나누기 → 필드별 pass → extracted 1건 저장 |
| `build.py` | 링크: extracted + reviewed 합치기, 재게시 묶기, '모집'만 남겨 scholarships.json 저장 |
| `check_rules.py` | 회귀 테스트: 규칙 정답 세트. **규칙을 고친 뒤 꼭 실행한다** |

## 구조: 컴파일러처럼 단계를 나눈다

```
raw JSON (본문 + 첨부)
  │ 1. 전처리      prepare_attachment_text   PDF의 \x00 공백, "선 발 대 상" 붙이기, 표 구분선 삭제
  │ 2. 구문 분석   parser.parse              문단 트리: [자격] [금액] [기간] [서류] [우대] [일정] [방법] [기타]
  │ 3. 의미 분석   extract.pass_*            필드마다 "자기 문단"을 먼저 보고, 없으면 틀린 값을 만드는 문단을 빼고 본다
  │      └ 어휘 분석 rules.extract_*         날짜·금액·학년·구간 정규식, 사전(dictionary.py)으로 이름 찾기, 앞뒤 문맥 거르기
  │ 4. 중간 표현   data/extracted/{bidx}.json  값 + 근거 문장 + 경고(needs_check, unclear, filtered_conditions)
  │ 5. 링크        build.py                  검수값 덮어쓰기, 재게시 글을 대표 글에 묶기
  ▼ 6. 출력        web/public/scholarships.json
```

**왜 구문 분석을 먼저 하나.** 예전에는 금액·마감·학년 추출이 각자 본문 전체를 줄 단위로 훑었다. 그래서 "1순위: 4분위 이하"가 소득 상한으로, "면접심사: 11.28"이 마감일로, "미제출시 10구간으로 간주"(서류 안내)가 소득 상한으로 읽히는 것을 필드마다 따로 막아야 했다. 지금은 문단을 한 번 나누고, 각 필드는 자기 문단만 본다.

| 필드 | 먼저 보는 문단 | 없으면 보는 곳 |
|---|---|---|
| 금액 | 금액 | 우대·일정·방법·서류·기간을 뺀 나머지 |
| 마감일 | (제목) → 기간 | 우대·일정·방법·서류·금액을 뺀 나머지 |
| 학년·평점·점수·소득 | 자격 | 우대·일정·방법·서류·금액·기간을 뺀 나머지 (자격 값이 우선, 빈 것만 채움) |
| 학과·거주지 | 자격 | 우대·방법·일정을 뺀 나머지 (거주지는 그다음 제목) |
| 제출서류 | 서류 | 전체 |
| 그 외 조건 | 자격·우대 문단만 | — |
| 면접·중복 수혜 | 전체 | — |

문단 제목이 없는 짧은 공지는 문단이 `intro` 하나뿐이라, 예전처럼 텍스트 전체를 읽는 것과 같다.

**문단 나누기 규칙** (`parser.py`)
- **제목 줄**: `SECTION_WORDS`의 말이 콜론 앞 이름표(20자 이내)에 있거나, 콜론 없는 40자 이하 줄의 앞 15자 안에 있으면 제목이다. 한 줄에 여러 종류의 말이 있으면 가장 앞에 나온 말로 정한다 ("신청대상 및 제출서류" → 자격, "지원자 제출서류(가산점 증빙서류 외 …)" → 서류).
- **번호 단계**: 한국 공문서 순서 `1.` > `가.` > `1)`·`①` > `가)` > `○·-·※·◦` 기호 > 번호 없음.
- **트리**: 열린 문단을 스택에 쌓는다. 제목 줄은 같거나 깊은 단계의 문단을 닫고 새 문단을 연다 ("4. 지원자격" 안의 "- 우대사항:"은 안쪽 문단). 제목 아닌 줄은 그 단계로 끝나는 문단을 닫고 남은 맨 위 문단에 붙는다.
- **목록 이어 가기**: "1) 1순위 … 3) 3순위" 다음의 "4) 교수 추천 학생"처럼, 제목 줄 자체가 항목이던 목록과 같은 단계의 이름표 없는 줄은 그 목록의 다음 항목이다.
- **제목만 있는 문단** ("※ 제외대상 |", "❍ 구비서류", "지원대상: 아래 조건을 모두 충족하는 자"): 첫 항목의 번호 단계를 따른다. "❍ 구비서류" 아래 "① …"처럼 더 큰 번호를 써도 이어진다.
- 서류 문단 안의 "7) 우대조건(가산점 부여) 항목 증빙서류"는 새 문단이 아니라 서류 이름이다.

`parser.describe(parse(text))`로 문단 나눈 결과를 볼 수 있다.

구조를 바꾼 전후 비교 (71건, 2026-11-13): 정답 세트 42/42 그대로. 값이 바뀐 공지 5건은 모두 고쳐진 것이다 (895660 제출서류 1 → 11개, 895985 서류 안내의 "10구간" 제거, 897117 소득 상한 5 → 8 "소득분위 1~8구간", 896254 거주지의 "지급일시, 반드시" 제거, 897009 서류 1개 추가). 그 외 조건 문장에서는 금액·일정·방법 줄이 빠지고, 897174 우대 목록과 897503·897664 우선순위 표가 이름표를 달고 들어왔다.

## 처리 순서

1. **공지 종류** (제목만 본다): 결과 단어("지급완료", "심사 결과"…) → `결과`, 안내 단어("서약서", "박람회"…) → `안내`, 모집 단어 + 장학 단어 → `모집`, 나머지 → `확인필요`. **빌드에는 `모집`만 들어간다.**
   - **라벨** (`classify_label`): 이벤트 묶기 단계가 같은 장학금의 공지들(모집 → 수정 → 완료)을 묶고 마지막 공지로 상태를 정할 때 쓴다. 한 공지에 여러 신호가 있으면 더 나중 상태를 고른다 (완료 > 수정 > 모집).

     | 라벨 | 조건 | 예 |
     |---|---|---|
     | `완료` | 공지 종류가 `결과`이거나, 모집 공지 제목에 `CLOSED_WORDS`(마감·선발완료·모집완료·종료) | "(지급완료) …", "… 모집 안내(마감)", "(신청기간 연장) … (선발완료)" |
     | `수정` | 모집 공지 제목에 `UPDATE_WORDS`(연장·변경·정정·(수정)·재공고) | "… 선발 안내(기한 연장: ~9. 23.)", "… 신청 안내(수정)" |
     | `모집` | 나머지 모집 공지 | |
     | `null` | 공지 종류가 `안내`·`확인필요` (장학금 모집·수정·완료 공지가 아님) | "등록금 분할납부 2차 납부 안내", "장학생 서약서 제출 및 지급 일정 안내" |

     시험 데이터 238건: 모집 102, 수정 5, 완료 79(마감 59, 결과 12, 모집완료 5, 선발완료 3), 없음 52. 라벨이 없는 것은 대부분 등록금 납부·튜터 모집·서류 제출 안내다. 공지 종류 규칙이 놓친 모집 공지("국가근로장학생 교체_(주)피플즈", "연구 장학금 지원 안내")는 라벨도 없으니 검수에서 `{"notice_kind": "모집", "label": "모집"}`으로 고친다.
2. **유형**: 근로장학 게시판(`bnum=57138`)이거나 제목에 "근로" → `근로`, "(홍보)"·"재단"·"장학회" → `교외`, 나머지 → `교내`.
3. **금액**: 금액 단어가 있는 줄에서 등록금 비율 → 시급 → 만원 → 원 순서로 찾는다. 같은 줄에서 소득 단어("차상위", "소득")보다 뒤에 나오는 금액은 소득 기준일 수 있어 쓰지 않는다. "또는", "택1"이 있으면 값은 첫 금액, `text`는 줄 전체로 둔다.
4. **마감일**: 제목의 `~11/12`을 먼저 보고(연장되면 제목이 바뀌므로), 없으면 본문의 "신청기간", "까지" 줄에서 마지막 날짜를 쓴다. 발표·면접·근무기간 줄은 건너뛴다. "선발 완료시까지" 같은 상시 모집은 `deadline: null`, `deadline_text: "상시 모집 (…)"`로 두고 확인 필요로 표시하지 않는다.
5. **조건**: 학년, 최소 평점(`gpa_min`, 4.5 만점), 최소 점수(`score_min`, 100점 만점), 소득 구간 상한. "3학년 이상"은 3~4학년, "2학년 이하"는 1~2학년으로 읽는다. 우대·순위는 아래 "앞뒤 문맥 거르기"로 뺀다. 소득 언급만 있고 값을 못 뽑으면 `eligibility.unclear`에 넣는다.
6. **학과·거주지**: 아래 "학과·거주지 규칙" 참고.
7. **그 외 조건 (문장형)**: 아래 "그 외 조건" 참고.
8. **준비 부담**: "제출서류" 다음 목록 중 서류 이름처럼 보이는 것만 남긴다. 본문에 "면접"이 있고 바로 뒤에 "없음, 생략, 실시하지 않음"이 없으면 면접 있음.
9. **근거 문장**: 금액·마감·중복 제한·학과·거주지는 값을 뽑은 원문 줄을 `evidence`에 남긴다. 규칙은 원문에 있는 글자만 뽑으므로 숫자를 지어내지 않는다.

못 찾은 값은 `null`로 두고 `needs_check`에 이름을 넣는다. 그 값은 검수에서 채운다.

## 학과·거주지 규칙

이름 찾기는 쉽고, 어려운 건 **그 이름이 자격 조건인지** 판단하는 것이다. 그래서 두 단계로 한다.

1. **이름 찾기**
   - 학과: `dictionary.py`의 학과·단과대·계열 이름. 긴 이름부터 찾아서 "벤처경영학과" 안의 "경영학과"는 따로 잡지 않는다. "대상, 자격, 재학생, 전공자" 같은 말이 있는 줄에서만 찾는다.
   - 거주지: 시·도 목록과 `○○시/군/구` 패턴. "거주, 주민등록, 출신, 구민" 같은 말이 있는 줄에서 찾는다. "서울과학기술대학교"의 "서울"처럼 뒤에 다른 글자가 붙은 것은 지역으로 보지 않는다.
   - 본문에서 못 찾으면 제목을 본다. "은평구민", "거창군 지역출신"은 확실한 조건, "통영시 저소득 대학생 장학금"처럼 이름만 있으면 값은 넣되 `unclear`에 넣는다.
2. **이름 앞뒤를 보고 거르기** (`config.py`의 단어 목록)

| 경우 | 보는 곳 | 예 | 결과 |
|---|---|---|---|
| 우대·문의·위치 문맥 (`NOT_CONDITION_WORDS`) | 이름 앞 25자, 뒤 12자 | "학교인근 거주자 **우대**", "**관련학과**: 화공생명공학과", "**문의**: 전기정보공학과 사무실", "서울 **소재** 대학", "**신청방법**: 방문**접수** (서울특별시 은평구 …)" | 거름 |
| 앞 줄에 이어 쓴 설명 (`CONTINUATION_MARKS`) | 줄이 `※`, `-`로 시작하면 앞 줄 | "우대사항: 아래 학과" 다음 줄 "- 컴퓨터공학과 재학생" | 거름 |
| 제한 없음 (`NO_LIMIT_WORDS`) | 뒤 12자 | "거주지 **무관**" | 거름 |
| 제외 조건 (`EXCLUDE_AFTER_WORDS`) | 뒤 12자 | "건축학전공 **제외**" | 거르고 `unclear`에 넣음 (제외 조건은 아직 필드가 없음) |

- 거른 것은 `data/extracted/{bidx}.json`의 `filtered_conditions`에 이유와 함께 남는다. 검수할 때 잘못 거른 게 없는지 여기서 본다.
- 단과대("공과대학")나 계열("공학계열")은 어느 학과까지인지 공지마다 달라서 값은 넣고 `unclear`에 넣는다.
- 거주지가 여러 곳이면 `"은평구, 서울특별시"`처럼 쉼표로 잇는다.

## 그 외 조건 (`eligibility.other_conditions`)

"학칙에 의한 징계사실이 없는 자", "북한이탈청소년", "경제적 사유로 학업에 어려움이 있는 학생"처럼 **값으로 바꿀 수 없는 조건**은 해석하지 않고 원문 문장을 목록으로 따로 담는다. 화면에서는 필터에 쓰지 않고 카드에 읽기용으로 보여 준다.

**우대·가산점·우선순위**도 버리지 않고 같은 목록에 담되, 앞에 이름표를 붙인다. **이름표가 없는 문장만 꼭 갖춰야 하는 자격**이다.

| 이름표 | 붙는 줄 (`PREFERENCE_TAGS`) | 예 |
|---|---|---|
| (없음) | 자격 조건 | `"학칙에 의한 징계사실(학사징계 포함)이 없는 자"` |
| `제외:` | "제외 대상 : …" | `"제외: 신규학기에 타 기관 장학금 수혜 대상인 학생"` |
| `우선순위:` | 순위·우선 | `"우선순위: 1순위: 국가유공자 본인이 본교에 재학중인 학생"` |
| `가산점:` | 가산 | `"가산점: 리더십 활동 유경험자 및 특별재능 보유자는 …"` |
| `우대:` | 우대·희망사항·관련학과 | `"우대: ChatGPT, Claude, 생성형 AI 서비스 활용 경험자"` |

한 줄에 여러 말이 있으면 위 표 순서(우선순위 → 가산점 → 우대)로 먼저 맞는 것을 붙인다. "1순위: 해당 가산점 항목 중 …"은 우선순위다.

1. `parser.py`가 나눈 문단 중 **자격 문단과 우대 문단만** 읽는다 (위 "구조" 절의 문단 나누기 규칙). 우대 문단 줄에는 문단 제목의 이름표가 기본으로 붙는다. 문단마다 최대 10줄.
2. 같은 문단 안에서도 줄마다 이름표를 다시 본다 (자격 문단 안의 "- 우대사항: …" 줄).
3. 쉼표로 끝난 줄은 다음 줄과 합친다.
4. 이름표 정하기: 줄에 우대·가산·순위 말이 있으면 그것, 번호 없이 앞 줄에 이어 쓴 줄이면 앞 줄 것 ("- 우대 사항:" 아래 줄들), 아니면 문단 제목의 것.
5. 빼는 줄
   - 문단 제목만 있는 줄 ("4. (재단)지원자격", "- 우대 사항:")
   - 신청 방법·서류 안내 줄 ("제출서류", "증빙서류", "신청 시", "참고", "첨부" …, `CONDITION_NOT_WORDS`)과 "09:00", "11.10(화)" 같은 일정 줄
   - 이름표 없는 줄 중 학년·평점·점수·소득처럼 이미 값으로 뽑는 조건만 있는 줄 ("본교 재학생 2~4학년, 성적 3.0 이상")
6. 문장은 100자, 목록은 12개까지.

학년·평점·소득 같은 값 필드에는 우대·순위 값이 들어가지 않는다 (아래 "앞뒤 문맥 거르기"). 같은 내용이 `other_conditions`에 이름표를 달고 남는다.

## 앞뒤 문맥 거르기 (학년·성적·소득·금액·면접·학과)

예전에는 "우대·가산"이 있는 **줄 전체**를 버렸다. 그러면 "지원자격: 3학년 재학생 (2학년 우대)"에서 진짜 조건 "3학년"까지 버린다. 지금은 **값 하나하나의 앞뒤 몇 글자**를 보고 그 값만 거른다. 단어 목록은 `config.py`에 있다.

| 필드 | 보는 곳 | 거르는 말 | 예 |
|---|---|---|---|
| 학년·평점·점수·소득 | 값 앞 12자 / 뒤 10자 | 앞: 우대·가산·순위·우선, 뒤: 우대·우선·가산 | "(2학년 **우대**)", "**1순위**: 4분위 이하", "(3구간 이하 **우선** 선발)" |
| 같은 필드, 줄 전체 | 콜론 앞 이름표 | 우대·가산·순위·우선·희망 | "**우대사항**: …, 2학년 이하" |
| 금액 | 값 앞 12자 | 예산·작년·전년·지난해 | "총 **예산** 5,000만원 범위 내 1인당 200만원" → 200만원 |
| 면접 | "면접" 뒤 12자 | 없음·없이·생략·미실시·실시하지 않 | "면접 **없음**" → `false` |
| 학과 | 이름 바로 뒤 (다른 학과 이름은 건너뜀) | 에서 | "정보통신대학 컴퓨터공학과**에서는** …" → 공지를 낸 학과라 조건 아님. "산업공학과 동문회에서는"은 사이에 다른 말이 있어 조건으로 둔다 |

정답 세트(`check_rules.py`, 37문장)로 잰 결과: 예전 규칙 26/37 → 지금 37/37 (2026-11-13). 실제 71건에서 바뀐 값은 2개였고 둘 다 맞게 고쳐졌다: 895588 학년 `[3]` → `[3, 4]` ("3학년 이상"), 897737 주관 학과 제거.

## 검수 (`data/reviewed/{bidx}.json`)

틀린 값만 적는다. 안쪽 필드는 그 필드만 덮어쓴다.

```json
{
  "_comment": "포스터 보고 입력",
  "amount": { "type": "lump_sum", "value": 3000000, "text": "300만원" },
  "deadline": "2026-11-20"
}
```

검수 파일에서만 쓰는 키:

| 키 | 뜻 |
|---|---|
| (추출 결과의 아무 필드) | 그 값을 덮어쓴다. 안쪽 필드는 그 필드만 바뀐다: `{"amount": {"value": 3000000}}` |
| `exclude` | `true`면 화면 목록에서 뺀다. 원본·추출 결과는 그대로 남아서, 지우면 다시 들어간다 |
| `_comment` (`_`로 시작하는 키) | 메모. 빌드가 무시한다 |

- 모집이 아닌데 `모집`으로 분류됐으면 `{"exclude": true}`
- 모집인데 다른 종류로 분류됐으면 `{"notice_kind": "모집"}`
- 검수 파일이 있는 항목은 빌드 결과에 `reviewed: true`가 붙는다.
- 재게시 묶음이 틀렸으면 `{"duplicate_of": null}`로 풀고, 같은 공지인데 안 묶였으면 `{"duplicate_of": "대표 bidx"}`로 묶는다.

## 재게시 묶기 (`duplicate_of`)

묶기는 **크롤러가 한다** ([crawler/README.md](../crawler/README.md) "재게시 묶기", 2026-11-13 결정). 크롤러는 **제목으로만** 묶는다 (괄호 안 "(~11/6(금))"를 지우고 유사도 0.9 이상). 분류는 그 결과를 받아 **마감일로 한 번 더 나눈다.**

- `extract.py`
  - raw의 `duplicate_of`를 옮긴다.
  - **마감일로 나누기** (`split_by_deadline`): 같은 제목에 마감일만 다른 공지(같은 이름의 다른 차수 모집)는 크롤러가 한 묶음으로 만들 수 있다. 묶음 안에서 대표 글과 마감일이 다른 글은 따로 떼어, 같은 마감일끼리 새 묶음을 만든다. 새 대표는 크롤러와 같은 순서(본부 글 > 먼저 올라온 글 > `bidx`가 작은 글)로 고른다. 뗀 글에는 이유가 `duplicate_split`에 남는다 (빌드할 때 빠짐).
    - 마감일을 모르는 글은 대표 쪽에 남긴다 (다르다는 근거가 없다).
    - 제목에 "연장"이 있으면 같은 공지의 기간 연장이라 나누지 않는다.
  - 같은 대표를 가리키는 글 번호를 대표 글의 `also_posted_bidx`에 모은다. 재게시 글도 추출 파일은 남긴다 (검수에서 묶음을 풀 수 있게).
  - 정답 세트 `regroup` 5개로 확인한다. 2026-11-13 데이터(재게시 6건)에서는 모두 대표 글과 마감일이 같아 나뉜 글이 없다.
- `build.py`: 검수값을 덮어쓴 뒤 `also_posted_bidx`를 다시 모으고, `duplicate_of`가 있는 글은 화면 목록에서 뺀다. `duplicate_of` 필드는 화면에 넘기지 않는다.

## 첨부 텍스트 (`attachments[].text`)

크롤러가 첨부(pdf·hwp·hwpx·docx)에서 뽑아 준 텍스트를 본문 다음 입력으로 쓴다. 형식은 [crawler/README.md](../crawler/README.md) "첨부 텍스트" 참고.

1. **읽는 첨부**: `text_status`가 `ok`인 것만. 이름에 "질문, FAQ, 매뉴얼"이 있는 첨부는 예시 숫자가 많아 읽지 않는다 (`IGNORED_ATTACHMENT_WORDS`).
2. **공고문과 양식 나누기**: 이름에 "신청서, 지원서, 양식, 동의서, 추천서 …"가 있으면 양식이다 (`FORM_ATTACHMENT_WORDS`). 단 "공고, 안내, 모집요강"이 같이 있으면 공고문이다. 양식은 "| 학년 | 학년 |", "지원구간: 구간" 같은 빈칸이 값처럼 보여서 **제출서류 목록에만** 쓴다.
3. **다듬기** (`prepare_attachment_text`): PDF의 `\x00`·전각 공백을 보통 공백으로, "선 발 대 상"처럼 한 글자씩 띄운 말을 붙이고, 표 구분선 `| --- |` 줄을 지운다. 표 칸 `|`는 줄 안 구분으로 둔다.
4. **순서**: 필드마다 **본문 → 공고문** 순서로 보고 처음 찾은 값을 쓴다. 본문이 더 최신일 수 있어서다 (연장 공지). 학년·평점·점수·소득은 본문 값을 두고 빈 것만 채운다. 거주지는 본문 → 공고문 → 제목. 제출서류는 본문 → 공고문 → 양식. 면접은 어디든 "면접 있음"이 있으면 있음.
5. **표시**: 첨부에서 찾은 값의 근거 문장 앞에 `[첨부: 파일 이름]`을 붙이고, 채운 필드 이름을 `from_attachment`에 남긴다 (빌드할 때 빠짐). 요약은 본문만으로 만든다 (첨부 내용을 다시 게시하지 않는다).

첨부를 읽으면서 생긴 오인을 막으려고 같이 넣은 규칙:

| 문제 | 예 (실제 첨부) | 규칙 |
|---|---|---|
| 기준 금액 | "실 납부금액이 100만원 **미만**일 시 제외" | 금액 뒤에 "이상·미만·초과"면 건너뜀 (`AMOUNT_AFTER_SKIP`) |
| 계산 예시 | "① 등록금 **납부**액 \| 400만원 \| ② 다른 기관에서 **받은** 장학금 \| 200만원 \| ③ 신청금액(①-②)" | 금액 앞에 "납부·받은·수혜", 줄에 "①-②·예시·예를 들어"면 건너뜀 |
| 대상별 금액 | "고등학생 50만원, **대학생** 최대 100만원" | 앞에 "대학"이 있는 금액을 먼저 고름 |
