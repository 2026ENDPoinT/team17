# 공지량·본문 실측 스크립트

[docs/research-findings.md](../../docs/research-findings.md) 6절의 숫자를 만든 스크립트다. 개강·종강 시기처럼 공지가 몰리는 때에 다시 돌려서 비교하는 용도다.

> 행사 전에 만든 스크립트지만 해커톤 결과물에 써도 된다고 운영진에게 확인받았다 (2026-11-13).
>
> 이 스크립트는 **조사용**이다. 서비스용 크롤러의 출발점으로 쓸 수는 있지만, 파서가 정규식 기반이라 그대로 운영에 쓰기에는 약하다.

## 필요한 것

- Python 3.8 이상
- 외부 패키지 없음 (표준 라이브러리만 사용)

## 실행 순서

```bash
cd tools/research
python volume.py boards.txt out/volume.json 30
python summarize.py out/volume.json 30
python views.py out/volume.json out/views.json
```

| 스크립트 | 하는 일 | 걸리는 시간 (2026-11 기준) |
|---|---|---|
| `volume.py` | 게시판마다 목록을 `?page=N`으로 최대 10페이지까지 읽어 최근 N일(기본 30일) 글을 모은다 | 약 3~5분 |
| `summarize.py` | 고유 글 수, 하루 평균, 게시판 순위, 같은 제목 중복을 출력한다 | 즉시 |
| `views.py` | 호스트마다 최대 6건을 무작위로 골라 상세 페이지를 읽고 본문 길이·첨부·이미지·개인정보 패턴·마감 표현 비율을 출력한다 | 약 1분 |

결과 파일은 `out/`에 쌓이고, 이 폴더는 Git에 올라가지 않는다.

## 학교 서버 예의

- 같은 호스트에는 **요청 간격 1초**를 두고 순차로 요청한다. 다른 호스트끼리만 최대 6개를 병렬로 처리한다.
- User-Agent에 조사 목적을 적어 두었다. 바꾸지 않는다.
- 하루에 여러 번 돌리지 않는다. 개발 중 파서를 고칠 때는 `out/`에 저장된 결과나 `tests/fixtures/`의 저장된 HTML을 쓴다. ([팀 가이드](../../docs/team-ai-collaboration-guide.md) 7절)

## 게시판 목록 (`boards.txt`)

한 줄에 `사이트|게시판 이름|목록 URL` 형식이다. [docs/notice-sources.md](../../docs/notice-sources.md) 3절의 표에서 옮긴 것이다. 게시판이 추가되거나 바뀌면 두 곳을 같이 고친다.

## 알려진 한계

- `archidesign`(건축학전공)은 별도 CMS라 0건으로 나온다.
- `job|일반채용`, `job|추천채용`(로그인 필요)은 일반 게시판이 아니라 숫자가 정확하지 않다.
- 도서관은 JSON API라 이 스크립트 대상이 아니다.
- 고정 공지 판정은 "번호 칸이 숫자가 아님"(표형) 또는 `ico_notice` 아이콘(카드형)에 의존한다.
- 같은 제목 중복은 **완전 일치만** 센다. 제목이 조금 다른 사본은 세지 않으므로 실제 중복은 더 많다.
