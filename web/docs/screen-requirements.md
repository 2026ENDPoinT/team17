# 장학금 헌터 화면 요구사항

> 작성일: 2026-11-13. 사용자와 합의한 화면 구성 및 동작을 정리한다.
> 서비스 배경: [서비스 범위](../../docs/scholarship-mvp.md)
> 입력 형식: [개발용 JSON 샘플](../../data/scholarships.sample.json)
> 색상·패널·버튼·스크롤 기준: [디자인 규칙](design-guide.md)

## 1. 목표와 현재 범위

- 교내 게시판에 흩어진 장학금을 모아 금액·마감·지원 조건으로 비교한다.
- 사용자가 핵심 기능을 쉽게 찾고, 적은 조작으로 사용할 수 있도록 한다.
- 메인 블록만 보고 관심 없는 장학금을 빠르게 넘길 수 있도록 한다.
- 화면은 메인 목록·즐겨찾기 목록·장학금 상세로 구성한다.
- 메인 위에 필터를 선택하는 팝업을 제공한다. 독립적인 페이지로 이동하는 방식은 아니다.
- 현재 정렬은 **마감순·금액순**을 제공한다. 가성비순은 후속 작업으로 미룬다.
- 모바일은 현재 고려하지 않는다. 로그인·알림·사용자 프로필은 현재 구현 범위에 넣지 않는다.
- 공통 색상은 `web/theme.css`에서 관리한다. 메인은 웜그레이 배경·아이보리 패널·따뜻한 흰색 카드와 드롭다운·고동색 글씨·옅은 회갈색 기본 윤곽선을 사용한다. 팝업 테마와 상세는 이번 변경 대상이 아니다.
- 메인 필터 선택·초기화 버튼과 선택된 필터는 밤색 바탕·밝은 글씨다. 카드·드롭다운 호버는 연한 베이지 바탕·밤색 테두리, 필터 선택·초기화·선택된 필터 호버는 진한 밤색이다. 둥근 모서리는 유지한다.

## 2. 메인 화면

### 전체 배치

```text
┌──────────────── 상단 제목 바 ──────────────────────────┐
│ 장학금 헌터   교내 게시판의 장학금을 모아 비교하세요.   │
└───────────────────────────────────────────────────────┘
┌────────────── 왼쪽 목록 ─────────────┬──── 오른쪽 설정 ───┐
│ 장학금 블록                         │ 정렬               │
│ ┌────────────────────────────────┐ │                    │
│ │ 장학금명                       │ │ 정렬: 마감순       │
│ │ 금액                 마감 정보 │ │                    │
│ │ 지원 조건 1 · 조건 2 · 조건 3   │ │ 필터 [필터 선택]   │
│ │                                │ │ [교내 ×] [3학년 ×] │
│ └────────────────────────────────┘ │ 선택된 필터만 표시 │
│ 장학금 블록                         │ 필요 시 내부 스크롤│
│ …                                   │                    │
│ 위아래로 스크롤                     │ [필터 초기화]      │
└─────────────────────────────────────┴────────────────────┘
```

- 왼쪽에는 한 줄에 장학금 블록 하나를 배치한다.
- 왼쪽 목록은 화면 높이를 기준으로 정사각형에 가까운 비율로 표시한다. 가로 공간이 부족하면 너비를 줄인다. 기존 75:25 비율 대신 오른쪽 설정은 360px로 두고, 전체를 중앙 정렬한다.
- 서비스 제목은 목록과 오른쪽 설정의 합산 너비에 맞는 상단 둥근 바로 표시한다. 높이는 64px이며 제목 옆에 작은 한 줄 설명을 둔다. 설명이 길면 말줄임 처리한다.
- 오른쪽 정렬과 필터는 각각 별도의 둥근 사각형으로 구분한다. 필터 초기화 버튼은 필터 박스 안에 둔다.
- 왼쪽 목록은 세로로 스크롤하고, 오른쪽 영역은 고정한다.
- 오른쪽은 위에서부터 정렬 → 필터 → 필터 초기화 순서다.
- 오른쪽의 **필터 제목 옆에 필터 선택 버튼**을 둔다. 버튼을 누르면 필터 선택 팝업을 연다.
- 오른쪽 필터 공간에는 전체 선택지 대신 **실제로 적용된 필터만 2열**로 배치하고, 길어지면 내부 스크롤을 제공한다.
- 적용된 필터에는 제거 표시(`×`)를 두고, 클릭하면 해당 조건을 즉시 해제해 목록에 반영한다.
- 제목 영역을 향후 프로필로 쓸 가능성은 있지만, 현재는 제목으로만 사용한다.

### 장학금 블록의 정보

| 순서 | 정보 | 데이터 및 표시 규칙 |
|---|---|---|
| 1 | 장학금명과 모집 상태 | 왼쪽 `name`, 오른쪽 모집 중 / 마감 / 마감일 미확인. 모집 중인 수정 항목에만 수정됨 표시 |
| 2 | 금액과 마감 | 금액은 항상 표시하고, 날짜·D-day는 모집 중일 때만 같은 줄에 표시. 마감·마감일 미확인일 때 날짜 영역을 생략 |
| 3 | 핵심 지원 조건 | `eligibility`를 읽어 최대 3개 표시. 각 조건을 `-`로 시작하는 별도 줄로 나열 |

- 핵심 조건은 **학년 → 학과 → 성적 → 소득 → 거주지** 순서로 확인된 항목을 최대 3개 표시한다.
- 메인·즐겨찾기 공통 카드의 세 번째 정보 줄 오른쪽에 빨간 **마감 임박**을 표시한다. 한국 날짜 기준 마감 당일부터 7일 전까지 포함하며, 마감된 항목과 마감일 미확인 항목에는 표시하지 않는다.
- **더보기는 현재 구현하지 않는다.** 전체 지원 조건은 상세 화면에서 확인한다.
- 블록을 클릭하면 해당 장학금 상세 화면으로 이동한다.
- 마감 상태는 `closed: true`, `status: "완료"` 또는 한국 기준 오늘보다 이전인 마감일로 판정한다. 그 외에 마감일이 없거나 미확인이면 마감일 미확인으로 표시한다. 두 상태는 둘째 줄 날짜를 표시하지 않으며 상세에서는 기존 마감 정보를 유지한다.
- 모집 중이고 `notices`에 수정 공지가 있거나 `status: "수정"`이면 수정됨을 표시한다. 상태 영역에 마우스를 올리거나 카드를 키보드로 선택하면 작은 말풍선에 최신 수정 공지의 `posted_at`을 표시한다. 날짜가 없으면 미확인으로 표시하며, 실제 수정일과 구분해 "수정 공지 게시일"이라고 쓴다.
- 불확실하거나 확인되지 않은 정보는 **미확인**으로 표시한다.
- 금액은 일시금·등록금 비율·시급의 단위를 구분한다. 등록금 비율을 임의로 원화로 바꾸지 않는다.
- 유형·서류·면접·요약 등은 메인 블록에 추가로 나열하지 않는다.

### 필터와 정렬

- 필터 종류: 유형, 학년, 학과, 모집 중만 보기.
- **유형**은 교내·교외·근로를 구분하며 그룹 내 복수 선택을 허용한다. 하나라도 일치하면 해당 그룹을 통과한다(OR).
- **학년**은 1·2·3·4학년이며 그룹 내 복수 선택을 허용한다. 하나라도 지원 학년에 포함되면 해당 그룹을 통과한다(OR).
- **학과**는 하나만 선택한다. 다른 학과를 누르면 기존 선택을 교체하고, 선택된 학과를 다시 누르면 해제한다.
- 학과 선택지는 `docs/notice-sources.md` 2절 위계 트리에서 추출한 학과·학부·전공 **55개**다. 본부·지원기관·단과대학은 선택지에서 제외하고, 학부와 소속 전공은 각각 문서에 나온 이름으로 제공한다. 학교 서버에 요청하지 않는다.
- **모집 중만 보기**는 켜짐/꺼짐으로 선택한다.
- 서로 다른 그룹은 **AND**로 결합한다. 선택하지 않은 그룹은 결과를 제한하지 않는다.
- 선택한 학년·학과 등 조건이 `null`이거나 불확실한 항목(`eligibility.unclear`, `needs_check`)이면 해당 필터 결과에서 제외한다. 선택하지 않은 그룹의 미확인 값 때문에 제외하지는 않는다. 학과 이름은 문서의 표기와 정확히 일치하는 값을 기준으로 비교한다.
- 모집 중만 보기는 `closed: true`인 항목과 마감일이 한국 기준 오늘보다 이전인 항목을 제외한다. 마감일이 없거나 잘못되었거나 미확인인 항목도 제외한다.
- 마감일 당일은 포함한다. 별도 시각 정보로 판정하지 않으므로 정확한 마감 시각은 공식 공지를 확인하라는 안내를 제공한다.
- 필터 선택은 팝업 안에서 켜짐/꺼짐 버튼으로 조작한다. 팝업의 본문·상단·하단은 아이보리로 통일하고, 그룹은 별도 배경 없이 간격과 구분선으로 나눈다. 팝업 뒤 배경은 웜그레이로 유지하고 외곽은 고동색 테두리로 구분한다. 모든 버튼은 크림색 바탕·고동색 글씨·둥근 모서리로 통일하고, 호버는 연한 베이지 바탕·밤색 테두리로 표시한다. 선택된 옵션은 샌드 베이지 `#DED0BE`(`--color-sand`) 바탕과 밤색 안쪽 테두리, 굵은 글씨로 구분한다.
- 유형·학년의 복수 선택과 학과의 단일 선택은 팝업의 임시 상태에서 처리한다. 팝업에서 선택만 바꿀 때는 메인 결과를 변경하지 않고, **적용 버튼을 눌렀을 때만** 메인에 반영한다.
- 최종 결과는 **메인에 적용된 최신 필터 상태**와 일치해야 한다. 팝업의 임시 선택은 적용 전까지 계산·저장 대상이 아니다.
- 첫 방문에는 필터가 선택되지 않은 상태로 전체 목록을 보여준다. 정렬 기본값은 마감순이다.
- 메인 오른쪽의 필터 초기화 버튼은 적용된 필터를 모두 해제하고 즉시 목록에 반영한다. 팝업 안의 초기화와는 적용 시점이 다르다.
- 필터 변경은 브라우저에 불러온 데이터를 다시 계산해 목록을 갱신한다. JSON을 매번 다시 요청할 필요는 없다.

### 정렬 드롭다운과 금액 유형

- 정렬 기준은 드롭다운에서 **마감순 / 금액순** 중 하나를 선택한다. 기본값은 마감순이다.
- **금액순을 선택했을 때만** 정렬 드롭다운 아래에 금액 유형 드롭다운을 표시한다.
- 유형은 **일시금 / 등록금 비율 / 시급**이고, 하나만 선택할 수 있다. 금액순으로 전환하면 일시금을 기본 선택한다.
- 금액 유형 드롭다운은 항상 하나의 유형을 선택하며, 다른 항목을 고르면 선택을 교체한다.
- 필터 박스는 최소 높이를 확보해 선택된 필터가 눌려 사라지지 않게 한다. 화면 높이가 부족하면 오른쪽 설정 전체를 스크롤한다.
- 금액순에서는 기존 필터 조건을 통과한 항목 중 **선택한 금액 유형만** 남기고, `amount.value`가 큰 순서로 정렬한다. 서로 다른 단위는 비교하지 않는다.
- 숫자 금액이 없거나 미확인인 항목은 금액순 결과에서 제외한다. `unknown` 유형은 선택지에 넣지 않는다.
- 금액이 같으면 기존 마감순 비교를 적용한다. 마감까지 같으면 원래 입력 순서를 유지한다.
- 마감순으로 돌아가면 유형 선택 영역을 숨기고 금액 유형 제한을 해제한다. 기존 필터 선택은 유지한다.
- 필터 초기화는 일반 필터만 해제한다. 정렬 기준과 금액 유형은 유지한다.
- 정렬 기준이나 금액 유형 변경은 즉시 목록에 반영하고, 왼쪽 목록 스크롤을 맨 위로 초기화한다.
- 상세의 이전·다음 이동은 금액 유형 제한과 정렬까지 적용된 표시 목록을 그대로 사용한다.

### 필터 선택 팝업

```text
┌────────────── 필터 선택 ──────────────┐
│ 유형 · 학년 · 학과 · 모집 중만 보기 │
│ 선택지를 클릭해 추가 또는 해제       │
│                                      │
│ [초기화]             [취소] [적용]   │
└──────────────────────────────────────┘
```

- 좁은 오른쪽 영역 대신 넓은 팝업 안에서 필터를 선택한다. 현재 배치는 최대 너비 960px, 선택지는 기본 3열·학년 4열이고, 선택 영역만 스크롤한다. 제목과 초기화·취소·적용 버튼은 계속 보이도록 한다. 세부 시각 디자인은 후속 조정한다.
- 팝업을 열 때 메인의 **적용된 필터를 복사해 임시 필터 상태**를 만든다. 배열 등 내부 값도 복사해 원본 상태와 공유하지 않는다.
- 팝업의 버튼을 클릭하면 해당 조건을 임시 상태에 추가하거나 제거한다. 메인의 적용 상태와 표시 목록은 그대로 유지한다.
- **초기화**는 팝업의 임시 선택만 모두 해제한다. 초기화 후 적용해야 메인 필터도 해제된다.
- **적용**은 임시 필터 상태를 `main.js`에 전달한다. 메인이 이를 적용 상태로 반영하고 필터·정렬 결과 및 오른쪽 선택 표시를 갱신하며 팝업을 닫는다.
- **취소하거나 적용하지 않고 닫으면** 임시 상태를 버린다. 메인의 필터와 목록은 바꾸지 않는다.
- 다시 열면 버렸던 임시 상태가 아니라 현재 메인에 적용된 필터를 다시 복사한다.
- 팝업의 임시 상태는 `sessionStorage`에 저장하지 않는다. 적용된 상태만 기존 저장·복원 흐름을 따른다.
- 취소 버튼 또는 Esc로 닫으면 적용하지 않는다. 바깥 영역 클릭으로는 닫지 않는다. 검색창은 현재 범위에 포함하지 않는다.

### 스크롤과 화면 상태

- 팝업 적용·메인 필터 제거·메인 초기화로 적용 상태가 바뀌면 왼쪽 목록의 스크롤을 **맨 위로 초기화**한다. 팝업 안의 임시 선택이나 취소는 목록 스크롤에 영향을 주지 않는다.
- 상세에서 목록으로 돌아오면 기존 필터·정렬과 **왼쪽 스크롤 위치를 유지**한다.

| 상태 | 왼쪽 영역 표시 |
|---|---|
| 결과 없음 | 블록 없이 `선택된 필터에 적합한 장학금이 없습니다.` |
| 로딩 중 | 중앙에 회전 표시와 `로딩중` |
| 데이터 불러오기 실패 | `정보를 불러오는데 실패했습니다.` |

## 3. 상세 화면

### 전체 배치

```text
       화면 좌우에 여백 · 좌우 영역 비율 1:1
검수 여부 (박스 바깥 위)
┌──── 왼쪽 핵심 정보 ─────┐    ┌─────────────────────────────┐
│                        │    │ 카테고리                    │
│                        │    │ 요약문 (왼쪽 정렬)          │
│ 장학금명               │    └─────────────────────────────┘
│ 금액        │ 마감     │    ┌──── 지원 자격 메모 ──────────┐
│ [원문 보기] │ [원문 보기] │  │ [지원 학년 : 3,4]           │
│ 각 칸 안에서 아래 펼침  │    │ [지원 학과 : 미확인]        │
│                        │    │ 그 외 전체 지원 조건        │
│ 핵심 지원 조건         │    └─────────────────────────────┘
│ [공식 공지 보기]       │    ┌──── 준비 사항 메모 ──────────┐
└────────────────────────┘    │ 제출 서류 · 면접 여부       │
┌──── 왼쪽 이동 버튼 ─────┐    └─────────────────────────────┘
│ [이전 장학금] [다음 장학금] │ ┌──── 주의 사항 메모 ──────────┐
│       [목록으로]       │    │ 중복 수혜 제한 · 미확인 조건 │
└────────────────────────┘    └─────────────────────────────┘
       스크롤 시 고정                 아래로 스크롤
```

- 상세 화면은 **왼쪽 위 핵심 정보, 왼쪽 아래 이동 버튼, 오른쪽 상세 정보**의 세 영역으로 구성한다.
- 왼쪽 이동 버튼은 화면의 왼쪽 영역 하단에 고정하고, 남은 높이에서 핵심 정보 내부만 스크롤한다. 오른쪽 메모는 독립적으로 스크롤한다.
- 핵심 정보와 이동 버튼 사이에는 24px 여백을 둔다. 핵심 정보의 둥근 외곽에서 12px 안쪽에 메인과 같은 얇은 스크롤 막대를 배치한다.
- 현재 확정한 것은 정보 배치다. 종이 질감·색상·장식·글씨체는 추후 결정한다.
- 상세 화면의 좌우 비율은 **1:1**이다.
- 상세는 메인의 콘텐츠 너비 계산을 기준으로 중앙에 배치하고 위아래 여백 32px, 좌우 최소 40px를 둔다. 좌우 간격은 24px다. 검수 배지를 공통 상단 행에 두고 왼쪽 핵심 정보와 오른쪽 첫 메모의 위 경계를 맞춘다.
- 상세도 웜그레이 배경·아이보리 패널·따뜻한 흰색 조건 카드·고동색 글씨·옅은 회갈색 윤곽선을 사용한다. 버튼은 밤색 바탕과 밝은 글씨이며 호버는 진한 밤색이다.

### 왼쪽 이동 버튼

- 첫 줄에 **이전 장학금·다음 장학금**, 그 아래에 **목록으로** 버튼을 배치한다.
- 이동 버튼은 글자 길이와 내부 여백에 맞춰 짧게 만들고 왼쪽 영역 가운데에 모은다. 목록으로 버튼을 전체 너비로 늘리지 않는다.
- 이전·다음은 원본 데이터 순서가 아닌 **현재 필터·정렬이 적용된 목록 순서**를 따른다.
- 첫 항목에서는 이전 버튼을, 마지막 항목에서는 다음 버튼을 비활성화한다. 한 건뿐이면 둘 다 비활성화한다.
- 목록으로 돌아오면 기존 필터·정렬과 왼쪽 목록의 스크롤 위치를 유지한다.
- 이전·다음 장학금으로 이동하면 **상세 화면의 스크롤 위치를 맨 위로 초기화**한다.

### 상세 주소와 브라우저 이동

- 목록 URL은 `/#/`, 상세 URL은 `/#/scholarships/{id}` 형식으로 한다. `#` 앞의 경로는 배포 위치를 따른다.
- 상세 URL로 직접 접속하거나 새로고침해도 해당 장학금을 표시한다.
- **브라우저 뒤로 가기**를 지원한다. 이전 화면이 목록이면 기존 필터·정렬과 목록 스크롤 위치를 복원한다.
- 상세 데이터는 `main.js`가 보관하는 원본 목록의 선택 항목에서 가져온다. 목록에서 상세로 이동할 때 같은 데이터를 다시 요청하지 않는다.
- 직접 접속·새로고침 시에는 JSON을 읽은 뒤 URL의 장학금 ID로 해당 항목을 찾는다.
- 버튼은 주소 변경 이벤트를 호출하고, `main.js`의 공통 주소 처리 함수가 해당 화면을 그린다.
- 이전·다음 이동도 방문 기록에 남긴다. A → B → C로 이동한 뒤 브라우저 뒤로 가기를 누르면 B를 표시한다.
- 목록으로 버튼은 방문 기록을 한 단계 되돌리는 대신 목록 주소로 이동한다. 상세 주소로 직접 접속해도 목록에 갈 수 있어야 한다.
- 존재하지 않는 장학금이나 잘못된 주소에는 `장학금을 찾을 수 없습니다.` 안내와 목록 이동 버튼을 표시한다.

### 목록 설정 저장과 복원

- `settingStore.js`에서 필터·정렬 이름·금액 유형·왼쪽 목록 스크롤 위치를 `sessionStorage`에 저장한다.
- 목록을 표시하거나 스크롤하거나 상세로 떠날 때 현재 설정을 저장하고, 페이지가 닫히기 전에도 저장한다.
- 새로고침 시 설정을 읽어 목록을 계산하고, 목록을 그린 뒤 스크롤 위치를 복원한다. 같은 탭에서 설정이 유지된다.
- 원본 장학금 데이터와 함수는 저장하지 않는다. 정렬은 이름을 저장하고 해당 비교 함수로 다시 연결한다. 선택 항목은 상세 URL에서 읽는다.
- 저장 내용이 없거나 손상되면 기본 필터·마감순·스크롤 맨 위로 시작한다.
- 새로고침·목록 복귀 시 금액순 여부와 선택한 금액 유형도 복원한다. 금액 유형의 저장값이 없거나 잘못됐으면 일시금으로 복원한다.
- 적용된 유형·학년 배열, 학과 하나, 모집 중 여부를 저장·복원한다. 저장된 선택지가 유효하지 않으면 제외한다. 팝업 임시 상태는 저장하지 않는다.

### 왼쪽 핵심 정보

- 메인 블록과 동일하게 **장학금명·금액·마감·핵심 지원 조건**을 표시한다.
- 왼쪽 핵심 지원 조건은 메인처럼 하이픈이 붙은 왼쪽 정렬 목록으로 최대 3개를 표시한다. 줄바꿈 시에도 하이픈 뒤 시작 위치를 맞춘다.
- 검수 여부는 **왼쪽 핵심 정보 박스의 위쪽 경계 바깥**에 표시한다. 검수 문구의 시작 위치는 박스 내부 여백이 아니라 **박스의 왼쪽 테두리와 정렬**한다.
- `reviewed: true`는 검수 완료, `false`는 미검수로 구분하고, 값이 없으면 미확인으로 표시한다.
- **공식 공지 보기** 버튼을 누르면 필터 팝업과 같은 크기의 관련 공지 팝업을 연다. 제목은 "관련 공지 보기"다.
- 이벤트의 `notices`를 공지마다 카드 하나로 표시한다. 왼쪽에는 `title`, 오른쪽에는 게시일 `posted_at`을 표시하며 카드를 누르면 해당 `url`을 새 탭으로 연다. 닫기 버튼이나 Esc로 팝업을 닫는다.
- 마감 시각 등 자세한 문구는 `deadline_text`를 참고하되, 확인되지 않은 값을 추측하지 않는다.
- 금액 아래에는 `amount.text`, 마감 아래에는 `deadline_text`를 펼치는 **원문 보기 버튼을 각각 하나씩** 둔다.
- 금액과 마감은 가로로 나란히 배치하고, 두 칸은 **가로 너비를 1:1로 나눈다.** 각 원문 설명은 해당 칸의 너비 안에서 줄바꿈되어 펼쳐진다.
- 화면이 낮거나 원문을 펼치면 핵심 정보 내부 스크롤을 사용하며, 이동 버튼은 계속 표시한다.
- 두 원문 설명은 기본적으로 접어 두고, 해당 버튼을 누르면 바로 아래에 펼쳐지며 다시 누르면 접힌다. 각 토글은 독립적으로 동작한다.
- 원문 보기는 공지 전체가 아니라 해당 항목의 설명만 표시한다. 값이 없으면 펼친 내용에 미확인으로 표시한다.
- 앞선 구상의 유형 배지·짧은 소개 대신, 최종 합의한 위 핵심 정보를 기준으로 구성한다.

### 오른쪽 세부 정보

| 구역 | 표시 정보 | 데이터 |
|---|---|---|
| 요약·카테고리 | 별도 제목 없이 카테고리 아래에 요약문을 왼쪽 정렬. `카테고리 :`, `요약 :` 표시는 생략. 지원 자격 메모보다 위에 배치 | `summary`, `category` |
| 지원 자격 | 학년·학과·최소 성적·최대 소득분위·거주지 등 전체 조건 | `eligibility` |
| 준비 사항 | 제출 서류 이름 전체, 면접 여부 | `burden.documents`, `burden.interview` |
| 주의 사항 | 중복 수혜 제한 여부, 확인되지 않은 조건 | `duplicate_restriction`, `eligibility.unclear` |

- 지원 자격은 왼쪽의 핵심 요약보다 자세하게 보여주며, 각 조건을 **항목명 : 값** 형태의 블록으로 배치한다.
- 예: `지원 학년 : 3,4`. 값이 없거나 불확실하면 `지원 학년 : 미확인`처럼 표시하며 제한 없음으로 단정하지 않는다.
- 학년·학과·성적(평점·백분위)·소득·거주지와 기타 조건을 다루고, `eligibility.unclear`로 분류된 항목은 확인된 값으로 표시하지 않는다.
- 신청 방법 메모도 초기 구상에 있었으나, 현재 JSON에는 전용 필드가 없다. 데이터를 받기 전에는 신청 방법을 지어내지 않고 공식 공지로 안내한다.
- **게시판 이름(`source.board`)과 대표 게시일(`source.posted_at`)은 상세 본문에 표시하지 않는다.** 개별 공지의 제목·게시일·원문 링크는 관련 공지 팝업에서 `notices`를 사용해 표시한다.
- 공식 공지를 확인하라는 안내를 제공한다.

- 오른쪽 카테고리는 작은 밤색 배지와 밝은 글씨로 표시한다. 요약은 배지 아래에 18px·굵기 600으로 표시하고 왼쪽에 밤색 세로선을 둔다.

### 후속 시각 작업

- 종이 질감·색상·장식·글씨체 등 시각 디자인은 추후 결정한다.
- 슬라이드 전환 형태의 화면 이동 애니메이션은 후속 검토 대상으로 두고, 현재 기능 구현 범위에는 포함하지 않는다.

## 4. 데이터 처리 원칙과 미정 사항

- 실제 입력은 `web/public/scholarships.json`, 개발용 형식 기준은 `data/scholarships.sample.json`이다.
- 샘플의 이름·금액·링크는 가상 값이다.
- 학생의 필터 입력은 브라우저 안에서만 사용하고 서버로 보내지 않는다.
- 공지 본문 전체·개인정보·첨부파일을 재게시하지 않는다. 공식 원문 링크로 연결한다.
- `evidence`와 `also_posted_bidx`는 기본 화면의 필수 표시 항목이 아니다.

아직 결정해야 하는 사항:

1. 조건 하나의 묶음 기준 등 메인 핵심 조건의 세부 표현.
2. 원본 데이터의 `null`이 제한 없음인지 정보 미확인인지에 대한 데이터 계약. 화면에서는 미확인으로 표시하고, 해당 필터를 선택하면 제외하는 정책으로 확정했다.
3. 미검수(`reviewed: false`) 데이터의 목록 포함 정책. 상세에서의 검수 여부 표시는 확정했다. 현재 구현은 필터 조건만 검사하며 검수 여부로 제외하지 않는다.
4. 메인 결과 건수 등 보조 정보의 표시 여부와 위치.

확정된 마감순 정렬은 **모집 중 → 마감됨 → 마감 미확인** 순서이며, 같은 그룹에서는 마감이 빠른 순으로 정렬한다. 같은 날짜는 기존 목록 순서를 유지한다.

## 5. 코드 구조

기술 스택은 **Vite + 순수 JavaScript**, Node.js 24다. 프레임워크 없이 가벼운 MVC 역할 분리를 사용한다.

| 파일 | 역할 |
|---|---|
| `data.js` | JSON 불러오기. Model의 데이터 접근 역할 |
| `logic.js` | 필터·정렬·지원 조건 가공. DOM 없는 순수 함수 |
| `renderMain.js` | 메인 목록·필터·로딩·오류·결과 없음 상태 그리기. View 역할 |
| `renderDetail.js` | 장학금 상세 정보·공식 공지 링크 그리기. View 역할 |
| `renderFavorites.js` | 즐겨찾기 전체 너비 목록·빈 상태·사라진 항목 안내 그리기 |
| `favoriteStore.js` | `localStorage`에 즐겨찾기 ID 저장·복원 |
| `renderFilterPopup.js` | 필터 선택 팝업, 임시 선택 상태와 적용·취소·초기화 이벤트 연결 |
| `filterOptions.js` | 유형·학년·문서에서 추출한 학과·금액 유형 선택지 상수. 화면과 저장 상태 검증에서 공유 |
| `main.js` | 이벤트 처리, 상태 변경, 로직 및 화면 갱신 연결. Controller 역할 |
| `settingStore.js` | 브라우저의 탭별 저장소에 목록 설정 저장·복원 |

- 상태는 하나의 객체에 모으고, 이벤트 처리에서는 상태를 변경해 화면 갱신으로 연결한다.
- 적용된 필터는 `main.js`의 상태에 보관하고, 팝업을 여는 동안만 별도의 임시 상태를 사용한다. 적용 이벤트를 통해서만 임시 선택을 메인에 전달한다.
- 데이터 흐름: 사용자 조작 → 상태 변경 → 로직 계산 → 화면 갱신.
- `main.js`는 원본을 `state.items`, 현재 표시할 계산 결과를 `state.visibleItems`에 따로 보관한다.
- 원본 로딩 및 필터·정렬·금액 유형 변경 후 `updateVisibleItems()`가 `logic.js`의 `filterScholarships()`로 필터링하고 `sortScholarships()`에 비교 함수를 전달해 표시 목록을 저장한다. 금액순이면 금액 유형 제한도 필터링에 포함한다. `updateMain()`이 그 목록과 선택 상태를 화면에 표시한다.
- 메인에서 들어간 상세의 이전·다음 이동은 `state.visibleItems`를 사용한다. 즐겨찾기에서 들어갔다면 즐겨찾기 목록 순서로 이동한다.
- 계산 로직에 DOM 코드를 섞지 않는다. 향후 프레임워크 전환 시 데이터·로직을 재사용할 수 있게 한다.
- 현재 샘플 목록·상세 정보·원문 토글·이전/다음/목록 이동·상세 URL·브라우저 뒤로/앞으로 가기·설정 복원·필터 팝업과 계산·선택 필터 즉시 제거를 구현했다. 후속 시각 작업은 미구현이다. 확정 요구사항과 구현 완료 범위는 구분한다.

## 6. 즐겨찾기 (2026-11-14)

- 메인 제목 오른쪽의 즐겨찾기 버튼으로 `#/favorites`에 진입한다.
- 제목은 '즐겨찾기', 오른쪽 버튼은 '뒤로가기'이며 메인으로 이동한다. 제목 아래에는 제목 바와 같은 너비의 스크롤 목록을 둔다.
- 메인 카드를 재사용하며 저장한 순서대로 표시한다. 메인 필터·정렬은 적용하지 않는다.
- 저장 ID는 이벤트 ID를 먼저 찾고, 없으면 `event-`를 제외한 값과 `notices.bidx`를 비교한다. 같은 이벤트로 합쳐진 즐겨찾기는 한 번만 표시한다.
- 찾을 수 없는 ID는 '더 이상 제공되지 않는 장학금입니다.'와 해제 버튼을 표시한다. 저장 목록이 비면 '즐겨찾기한 장학금이 없습니다.'를 표시한다.
- 상세 주소는 `#/favorites/scholarships/{id}`다. 직접 접속·새로고침해도 즐겨찾기 기준으로 이전·다음 이동과 목록 복귀를 연결한다.
- 상세에서 현재 항목을 해제해도 화면과 스크롤은 유지하고, 남아 있는 즐겨찾기만 이전·다음 이동 대상으로 삼는다. 즐겨찾기 목록으로 돌아가면 해제가 반영되고 목록 스크롤을 복원한다.
- ID는 브라우저의 `localStorage`에 저장하며 서버로 보내지 않는다.
