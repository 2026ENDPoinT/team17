# 장학금 헌터 화면 요구사항

> 작성일: 2026-11-13. 사용자와 합의한 화면 구성 및 동작을 정리한다.
> 서비스 배경: [서비스 범위](../../docs/scholarship-mvp.md)
> 입력 형식: [개발용 JSON 샘플](../../data/scholarships.sample.json)

## 1. 목표와 현재 범위

- 교내 게시판에 흩어진 장학금을 모아 금액·마감·지원 조건으로 비교한다.
- 사용자가 핵심 기능을 쉽게 찾고, 적은 조작으로 사용할 수 있도록 한다.
- 메인 블록만 보고 관심 없는 장학금을 빠르게 넘길 수 있도록 한다.
- 화면은 메인 목록과 장학금 상세 두 개로 구성한다.
- 현재 정렬은 **마감순만** 제공한다. 서비스 범위 문서의 금액순·가성비순은 사용자 결정에 따라 후속 작업으로 미룬다.
- 모바일은 현재 고려하지 않는다. 로그인·알림·사용자 프로필은 현재 구현 범위에 넣지 않는다.
- 질감·글씨체 등 구체적인 시각 디자인은 나중에 정한다. 필터의 선택 색상은 파란색으로 확정했다.

## 2. 메인 화면

### 전체 배치

```text
┌────────────── 왼쪽 75% ──────────────┬──── 오른쪽 25% ────┐
│ 장학금 블록                         │ 서비스 제목·설명   │
│ ┌────────────────────────────────┐ │                    │
│ │ 장학금명                       │ │ 정렬: 마감순       │
│ │ 금액                 마감 정보 │ │                    │
│ │ 지원 조건 1 · 조건 2 · 조건 3   │ │ 필터               │
│ │                                │ │ [선택지] [선택지]  │
│ └────────────────────────────────┘ │ [선택지] [선택지]  │
│ 장학금 블록                         │ 필요 시 내부 스크롤│
│ …                                   │                    │
│ 위아래로 스크롤                     │ [필터 초기화]      │
└─────────────────────────────────────┴────────────────────┘
```

- 왼쪽에는 한 줄에 장학금 블록 하나를 배치한다.
- 왼쪽 목록은 세로로 스크롤하고, 오른쪽 영역은 고정한다.
- 오른쪽은 위에서부터 제목·설명 → 정렬 → 필터 → 필터 초기화 순서다.
- 필터 선택지는 2열로 배치하고, 길어지면 내부 스크롤을 제공한다.
- 제목 영역을 향후 프로필로 쓸 가능성은 있지만, 현재는 제목으로만 사용한다.

### 장학금 블록의 정보

| 순서 | 정보 | 데이터 및 표시 규칙 |
|---|---|---|
| 1 | 장학금명 | `name` |
| 2 | 금액과 마감 | 같은 줄에 금액과 마감 날짜·D-day를 표시. `amount`, `deadline`, `deadline_text` 사용 |
| 3 | 핵심 지원 조건 | `eligibility`를 읽어 조건을 가로로 나열. 최대 3개 표시 |

- 핵심 조건은 **학년 → 학과 → 성적 → 소득 → 거주지** 순서로 확인된 항목을 최대 3개 표시한다.
- **더보기는 현재 구현하지 않는다.** 전체 지원 조건은 상세 화면에서 확인한다.
- 블록을 클릭하면 해당 장학금 상세 화면으로 이동한다.
- 불확실하거나 확인되지 않은 정보는 **미확인**으로 표시한다.
- 금액은 일시금·등록금 비율·시급의 단위를 구분한다. 등록금 비율을 임의로 원화로 바꾸지 않는다.
- 유형·서류·면접·요약 등은 메인 블록에 추가로 나열하지 않는다.

### 필터와 정렬

- 필터 종류: 유형, 학년, 학과, 모집 중만 보기.
- 유형은 교내·교외·근로를 구분한다.
- 필터는 켜짐/꺼짐 버튼으로 조작한다. 켜지면 파란색이 적용되고 꺼지면 선택 색상이 제거된다.
- 복수 선택을 허용하고, 선택 즉시 결과에 반영한다.
- 갱신 중 다른 필터가 선택되어도 최종 결과는 **가장 최근 선택 상태**와 일치해야 한다.
- 첫 방문에는 필터가 선택되지 않은 상태로 전체 목록을 보여준다. 정렬 기본값은 마감순이다.
- 필터 초기화 버튼은 필터 선택을 해제한다.
- 필터 변경은 브라우저에 불러온 데이터를 다시 계산해 목록을 갱신한다. JSON을 매번 다시 요청할 필요는 없다.

### 스크롤과 화면 상태

- 필터 변경 시 왼쪽 스크롤 위치를 유지할 필요는 없다. 구체적인 이동 위치는 아직 정하지 않았다.
- 상세에서 목록으로 돌아오면 기존 필터·정렬과 **왼쪽 스크롤 위치를 유지**한다.

| 상태 | 왼쪽 영역 표시 |
|---|---|
| 결과 없음 | 블록 없이 `선택된 필터에 적합한 장학금이 없습니다.` |
| 로딩 중 | 중앙에 회전 표시와 `로딩중` |
| 데이터 불러오기 실패 | `정보를 불러오는데 실패했습니다.` |

## 3. 상세 화면

### 전체 배치

```text
       화면 좌우에 여백 · 좌우 영역 비율 1:1
검수 여부 (박스 바깥 위)
┌──── 왼쪽 핵심 정보 ─────┐    ┌──── 요약·카테고리 메모 ─────┐
│                        │    │ 요약문 · 카테고리           │
│ 장학금명               │    └─────────────────────────────┘
│ 금액                   │    ┌──── 지원 자격 메모 ──────────┐
│ [원문 보기] → 아래 펼침 │    │ [지원 학년 : 3,4]           │
│ 마감                   │    │ [지원 학과 : 미확인]        │
│ [원문 보기] → 아래 펼침 │    │ 그 외 전체 지원 조건        │
│ 핵심 지원 조건         │    └─────────────────────────────┘
│ [공식 공지 보기]       │    ┌──── 준비 사항 메모 ──────────┐
└────────────────────────┘    │ 제출 서류 · 면접 여부       │
┌──── 왼쪽 이동 버튼 ─────┐    └─────────────────────────────┘
│ [이전 장학금] [다음 장학금] │ ┌──── 주의 사항 메모 ──────────┐
│       [목록으로]       │    │ 중복 수혜 제한 · 미확인 조건 │
└────────────────────────┘    └─────────────────────────────┘
       스크롤 시 고정                 아래로 스크롤
```

- 상세 화면은 **왼쪽 위 핵심 정보, 왼쪽 아래 이동 버튼, 오른쪽 상세 정보**의 세 영역으로 구성한다.
- 왼쪽 핵심 정보와 이동 버튼은 함께 묶어 스크롤 시 고정한다. 화면 높이가 부족하면 왼쪽 묶음도 스크롤할 수 있게 한다.
- 이동 버튼은 핵심 정보 아래에 여백을 두고 배치하며, 화면 맨 아래에 강제로 붙이지 않는다.
- 현재 확정한 것은 정보 배치다. 종이 질감·색상·장식·글씨체는 추후 결정한다.
- 상세 화면의 좌우 비율은 **1:1**이다.
- 화면 양쪽 바깥에 패딩을 두어 좌우 영역이 화면 중앙에 모이도록 배치한다. 구체적인 여백 크기는 시각 디자인 단계에서 조정한다.

### 왼쪽 이동 버튼

- 첫 줄에 **이전 장학금·다음 장학금**, 그 아래에 **목록으로** 버튼을 배치한다.
- 이전·다음은 원본 데이터 순서가 아닌 **현재 필터·정렬이 적용된 목록 순서**를 따른다.
- 첫 항목에서는 이전 버튼을, 마지막 항목에서는 다음 버튼을 비활성화한다. 한 건뿐이면 둘 다 비활성화한다.
- 목록으로 돌아오면 기존 필터·정렬과 왼쪽 목록의 스크롤 위치를 유지한다.
- 이전·다음 장학금으로 이동하면 **상세 화면의 스크롤 위치를 맨 위로 초기화**한다.

### 상세 주소와 브라우저 이동

- 장학금별로 구분되는 상세 URL을 제공한다. 구체적인 URL 표기 방식은 구현 시 정한다.
- 상세 URL로 직접 접속하거나 새로고침해도 해당 장학금을 표시한다.
- **브라우저 뒤로 가기**를 지원한다. 이전 화면이 목록이면 기존 필터·정렬과 목록 스크롤 위치를 복원한다.
- 상세 데이터는 `main.js`가 보관하는 원본 목록의 선택 항목에서 가져온다. 목록에서 상세로 이동할 때 같은 데이터를 다시 요청하지 않는다.
- 직접 접속·새로고침 시에는 JSON을 읽은 뒤 URL의 장학금 ID로 해당 항목을 찾는다.

### 왼쪽 핵심 정보

- 메인 블록과 동일하게 **장학금명·금액·마감·핵심 지원 조건**을 표시한다.
- 검수 여부는 **왼쪽 핵심 정보 박스의 위쪽 경계 바깥**에 표시한다. 검수 문구의 시작 위치는 박스 내부 여백이 아니라 **박스의 왼쪽 테두리와 정렬**한다.
- `reviewed: true`는 검수 완료, `false`는 미검수로 구분하고, 값이 없으면 미확인으로 표시한다.
- 여기에 **공식 공지 보기** 버튼을 추가한다. 대상 링크는 `source.url`이다.
- 마감 시각 등 자세한 문구는 `deadline_text`를 참고하되, 확인되지 않은 값을 추측하지 않는다.
- 금액 아래에는 `amount.text`, 마감 아래에는 `deadline_text`를 펼치는 **원문 보기 버튼을 각각 하나씩** 둔다.
- 두 원문 설명은 기본적으로 접어 두고, 해당 버튼을 누르면 바로 아래에 펼쳐지며 다시 누르면 접힌다. 각 토글은 독립적으로 동작한다.
- 원문 보기는 공지 전체가 아니라 해당 항목의 설명만 표시한다. 값이 없으면 펼친 내용에 미확인으로 표시한다.
- 앞선 구상의 유형 배지·짧은 소개 대신, 최종 합의한 위 핵심 정보를 기준으로 구성한다.

### 오른쪽 세부 정보

| 구역 | 표시 정보 | 데이터 |
|---|---|---|
| 요약·카테고리 | 요약문, 장학금 유형. 지원 자격 메모보다 위에 배치 | `summary`, `category` |
| 지원 자격 | 학년·학과·최소 성적·최대 소득분위·거주지 등 전체 조건 | `eligibility` |
| 준비 사항 | 제출 서류 이름 전체, 면접 여부 | `burden.documents`, `burden.interview` |
| 주의 사항 | 중복 수혜 제한 여부, 확인되지 않은 조건 | `duplicate_restriction`, `eligibility.unclear` |

- 지원 자격은 왼쪽의 핵심 요약보다 자세하게 보여주며, 각 조건을 **항목명 : 값** 형태의 블록으로 배치한다.
- 예: `지원 학년 : 3,4`. 값이 없거나 불확실하면 `지원 학년 : 미확인`처럼 표시하며 제한 없음으로 단정하지 않는다.
- 학년·학과·성적(평점·백분위)·소득·거주지와 기타 조건을 다루고, `eligibility.unclear`로 분류된 항목은 확인된 값으로 표시하지 않는다.
- 신청 방법 메모도 초기 구상에 있었으나, 현재 JSON에는 전용 필드가 없다. 데이터를 받기 전에는 신청 방법을 지어내지 않고 공식 공지로 안내한다.
- **게시판 이름(`source.board`)과 게시일(`source.posted_at`)은 표시하지 않는다.** 원문 링크(`source.url`)는 공식 공지 보기에서 사용한다.
- 공식 공지를 확인하라는 안내를 제공한다.

### 후속 시각 작업

- 종이 질감·색상·장식·글씨체 등 시각 디자인은 추후 결정한다.
- 슬라이드 전환 형태의 화면 이동 애니메이션은 후속 검토 대상으로 두고, 현재 기능 구현 범위에는 포함하지 않는다.

## 4. 데이터 처리 원칙과 미정 사항

- 실제 입력은 `web/public/scholarships.json`, 개발용 형식 기준은 `data/scholarships.sample.json`이다.
- 샘플의 이름·금액·링크는 가상 값이다.
- 학생의 필터 입력은 브라우저 안에서만 사용하고 서버로 보내지 않는다.
- 공지 본문 전체·개인정보·첨부파일을 재게시하지 않는다. 공식 원문 링크로 연결한다.
- `evidence`와 `also_posted_bidx`는 기본 화면의 필수 표시 항목이 아니다.

아직 결정해야 하는 사항:

1. 같은 필터 그룹 내 복수 선택과 서로 다른 그룹 사이의 결합 규칙.
2. 조건 하나의 묶음 기준 등 메인 핵심 조건의 세부 표현.
3. `null`이 제한 없음인지 정보 미확인인지에 대한 데이터 계약. 합의 전에는 미확인으로 표시한다.
4. 날짜만 있는 `deadline`과 별도 시각 필드가 없는 상황에서 모집 중 여부를 판단하는 세부 기준.
5. 미검수(`reviewed: false`) 데이터의 목록 포함 정책. 상세에서의 검수 여부 표시는 확정했다.
6. 메인 결과 건수 등 보조 정보의 표시 여부와 위치.

확정된 마감순 정렬은 **모집 중 → 마감됨 → 마감 미확인** 순서이며, 같은 그룹에서는 마감이 빠른 순으로 정렬한다. 같은 날짜는 기존 목록 순서를 유지한다.

## 5. 코드 구조

기술 스택은 **Vite + 순수 JavaScript**, Node.js 24다. 프레임워크 없이 가벼운 MVC 역할 분리를 사용한다.

| 파일 | 역할 |
|---|---|
| `data.js` | JSON 불러오기. Model의 데이터 접근 역할 |
| `logic.js` | 필터·정렬·지원 조건 가공. DOM 없는 순수 함수 |
| `renderMain.js` | 메인 목록·필터·로딩·오류·결과 없음 상태 그리기. View 역할 |
| `renderDetail.js` | 장학금 상세 정보·공식 공지 링크 그리기. View 역할 |
| `main.js` | 이벤트 처리, 상태 변경, 로직 및 화면 갱신 연결. Controller 역할 |

- 상태는 하나의 객체에 모으고, 이벤트 처리에서는 상태를 변경해 화면 갱신으로 연결한다.
- 데이터 흐름: 사용자 조작 → 상태 변경 → 로직 계산 → 화면 갱신.
- 계산 로직에 DOM 코드를 섞지 않는다. 향후 프레임워크 전환 시 데이터·로직을 재사용할 수 있게 한다.
- 현재 메인은 샘플 데이터의 목록 표시와 블록 클릭 시 상세 전환까지 구현했다. 상세에는 핵심 정보·검수 여부·개별 원문 토글·오른쪽 메모를 표시한다. 이동 버튼·상세 URL 및 브라우저 이동은 아직 연결하지 않았다. 확정 요구사항과 구현 완료 범위는 구분한다.
