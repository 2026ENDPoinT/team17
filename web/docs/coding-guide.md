# 화면 코드 작성 가이드

이 문서는 `web/`의 코드를 구현하거나 수정할 때 따르는 사용자 요청 규칙이다.

## 1. 요청한 함수 중심으로 구현한다

- 사용자가 요구한 함수를 중심으로, 요청한 범위만 구현한다.
- 편의나 구조 개선을 위한 보조 함수를 임의로 추가하지 않는다.
- 부가적인 함수가 필요하면 그 함수의 역할과 필요한 이유를 간략히 설명하고, 사용자에게 물어본 뒤 추가한다.

## 2. 모든 함수에 역할 주석을 단다

- 코드를 작성한 뒤, 작성하거나 수정한 모든 함수에 무슨 일을 하는지 한국어 주석을 단다.
- 일반 함수뿐 아니라 변수에 담은 화살표 함수와 이벤트 콜백에도 적용한다.
- 주석은 함수 선언이나 콜백을 등록하는 코드 바로 위에 짧게 적는다.

## 3. 구현 후 함수와 실행 흐름을 설명한다

- 구현하거나 수정한 함수는 이름과 역할만 나열하지 않고, **어느 스크립트에 정의되어 있고 어떤 흐름으로 동작하는지** 설명한다.
- 설명은 스크립트별로 묶고, 파일 이름과 함수 이름을 함께 표시한다. 실제 파일을 가리키는 링크도 제공한다.
- 각 함수에 다음 내용을 포함한다.
  1. **위치와 역할**: 어느 스크립트에 정의되어 있고 무엇을 담당하는지.
  2. **호출 시점과 호출자**: 시작할 때인지, 버튼을 눌렀을 때인지, 다른 함수가 호출하는지. 다른 파일의 함수라면 파일 이름도 함께 적는다.
  3. **입력**: 전달받는 값이 무엇이고 어디에서 온 값인지.
  4. **내부 처리 순서**: 데이터를 읽거나 상태를 바꾸거나 다른 함수를 호출하는 과정을 순서대로 설명한다.
  5. **결과와 다음 연결**: 무엇을 반환·저장·표시하고, 다음에 어느 스크립트의 함수 또는 이벤트로 이어지는지. 즉시 실행과 이벤트 등록은 구분한다.
- 관련 함수들의 설명 뒤에는 **사용자 조작 또는 시작 시점 → 파일명과 함수명 → 데이터·상태 변화 → 화면 표시** 순서로 전체 흐름을 정리한다.
- 버튼 이동, 최초 접속·새로고침, 브라우저 뒤로·앞으로 가기처럼 시작점이나 처리 과정이 다르면 흐름을 나누어 설명한다.
- JavaScript를 처음 접하는 사용자가 이해할 수 있는 쉬운 표현을 쓴다.
- 설명은 핵심 위주로 작성하되, 간결함을 이유로 파일 위치·호출 관계·내부 처리 흐름을 생략하지 않는다. 예시는 필요한 경우 하나 정도만 든다.
