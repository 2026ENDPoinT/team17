# events: 장학금 이벤트 묶기 (화면용 최종 빌드)

같은 장학금에 대한 공지들(모집 → 기한 연장·일정 변경 → 마감·결과)을 **이벤트 하나**로 묶어 화면이 읽을 `web/public/events.json`을 만든다.

- 담당: 크롤링 담당 (이 폴더는 이벤트 묶기 담당만 고친다)
- 입력: `data/extracted/{bidx}.json` (분류 담당), `data/reviewed/{bidx}.json` (공지별 검수), `data/reviewed/events.json` (묶음 검수)
- 출력 형식: [`data/events.sample.json`](../data/events.sample.json). 필드를 바꾸면 샘플과 이 문서를 같이 고치고 화면 담당에게 알린다.

## 실행

```bash
uv run python classifier/extract.py   # data/raw → data/extracted (분류 담당 단계)
uv run python events/build.py         # data/extracted + data/reviewed → web/public/events.json
```

| 파일 | 역할 |
|---|---|
| `group.py` | 묶기 규칙 (순수 함수): 공지 라벨 정하기, 장학금 이름·연도·학기·차수 뽑기, 같은 장학금 판단, 묶기 |
| `build.py` | 단계 연결: 입력 읽기 → 재게시 정리 → 라벨 → 묶기 → 묶음 검수 적용 → 이벤트 만들기 → 저장. 안전장치도 여기 있다 |

## 이벤트 항목 (`items[]`)

`data/scholarships.sample.json` 항목의 필드를 모두 가지고(화면 코드를 거의 그대로 쓸 수 있게), 아래가 더 있다.

| 필드 | 설명 |
|---|---|
| `id` | `event-{첫 공지 bidx}` |
| `status` | 마지막 공지의 라벨: `모집` / `수정` / `완료` |
| `grouped_by` | `auto`(규칙으로 묶음) / `reviewed`(묶음 검수로 바뀜) / `single`(공지 1건뿐이거나 안전장치) |
| `notices` | 이 장학금의 공지 목록, 게시일 순. `{bidx, label, title, board, url, posted_at, also_posted_bidx}` |

이벤트의 값을 정하는 규칙
- **상세가 있는 공지**: 라벨이 `모집`·`수정`인 공지와, 마감된 모집 공지(라벨 `완료`이고 `notice_kind`가 `모집`, 예: "… 모집 안내(마감)"). 결과 공지(라벨 `완료`, `notice_kind` `결과`)에는 상세가 없다.
- **상세 값**(금액·조건·서류·요약·유형·중복 제한): 상세가 있는 가장 최근 공지의 값. 비어 있으면 그 앞 공지 값으로 채운다. `title`, `source`(원문 링크)도 그 공지 것이다.
- **마감일**: 마감일이 있는, 상세가 있는 가장 최근 공지의 것. 게시일보다 앞선 마감일은 잘못 뽑은 값으로 보고 건너뛰고 `needs_check`에 `deadline`을 넣는다 (실제 예: 896003 "(수정)" 공지에서 `2025-10-05`가 뽑힘).
  - 마감일을 가져온 공지보다 뒤에 마감일을 뽑지 못한 수정 공지(기한 연장 등)가 있으면, `deadline`은 옛 날짜를 그대로 두고 `deadline_text`는 그 수정 공지 문장을 쓰며 `needs_check`에 `deadline`을 넣는다. 옛 마감일이 연장 전 날짜일 수 있어서다. 화면은 이 표시를 보고 "원문 확인"을 띄우고, 사람이 원문을 보고 `data/reviewed/{bidx}.json`에 그 공지의 `deadline`을 적으면 다음 빌드부터 바른 날짜가 나온다. 날짜와 상관없는 수정 공지(서류 변경 등)에도 표시가 붙을 수 있지만, 틀린 마감일을 조용히 보여 주는 것보다 낫다고 본다.
- **`closed`**: 상태가 `완료`이거나, 상세가 있는 가장 최근 공지가 마감 표시("(마감)" 등)면 `true`.
- **재게시**: 크롤러가 `duplicate_of`를 붙인 글은 대표 글과 같은 글이다. 따로 이벤트가 되지 않고 대표 글의 `also_posted_bidx`에 번호만 남는다. 이벤트의 `also_posted_bidx`는 모든 공지의 것을 모은 것이다.
- **상세가 있는 공지가 없는 이벤트**(결과 공지만 있는 것)는 내보내지 않는다. 라벨이 `null`인 공지(장학금 공지가 아님)도 넣지 않는다.

## 라벨과 묶기 규칙 (`group.py`)

**입력 약속.** 라벨은 분류가 `label` 필드로 준다 (2026-11-14 확정, 분류 브랜치 `feat/classifier`의 `classify_label`). 값은 `모집` / `수정` / `완료` / `null` 네 가지다. 분류는 "… 모집 안내(마감)"처럼 마감된 모집 공지에도 `완료`를 붙인다. 아래 필드가 없으면 오른쪽 방법으로 대신 읽는다.

| 필드 | 값 | 없을 때 |
|---|---|---|
| `label` | `모집` / `수정` / `완료` / `null`(장학금 공지가 아님, 이벤트에 넣지 않음). **필드가 있으면 값이 `null`이어도 그대로 쓴다** | 필드가 없는 옛 추출 결과만: `notice_kind`가 `결과` → 완료. `모집`이고 제목에 "연장, 수정, 변경, 추가 선발, 추가 모집, 재공지"가 있으면 수정, 아니면 모집. 그 외 → `null` |
| `year` | 2026 같은 정수 | 제목의 "2026학년도", "2026년", "2026-2학기", "26년" |
| `semester` | 1 / 2 | 제목의 "2학기", "상반기"(1), "하반기"(2) |
| `round` | 차수 정수 (1차, 제7회, 제22기) | 제목의 "2차", "제7회", "제22기" ("(수정 3차)"는 차수가 아님) |

장학금 이름은 분류의 `name`이 아니라 **제목**에서 만든다. 분류의 `name`은 괄호 속 재단 이름을 지워서 "[대림수암장학문화재단] 2026년 장학생 선발"이 "2026년 장학생 선발"이 되기 때문이다.

**같은 장학금 판단** (이벤트의 첫 공지와 비교)
1. 이름: 제목을 아래처럼 정리한 뒤 **완전히 같아야** 한다. 정리한 이름이 4자 미만이면 판단하지 않는다.
   - **괄호 정리 기준은 [`crawler/README.md`](../crawler/README.md) "재게시 표시 > 제목 정규화" 절이다** (2026-11-14 팀 결정). 이벤트는 크롤러 함수를 import하지 않고 `group.py`에 같은 목록(`_DATE_LIKE`, `_BRACKET_STATUS`, `_BOARD_LABEL`, `_AUDIENCE`, `_ORG_NAME`, `_IDENTIFIER`)을 둔다. 크롤러 목록이 바뀌면 여기도 같이 고친다. 원본 제목은 그대로 두고 비교할 때 만드는 임시 사본에만 쓴다.
     - 항상 지움: 날짜·기한, 상태 꼬리표("(마감)", "(홍보)", "(수정 3차)", "(교체 선발)" …), 분류 표시(한 글자 "(재)", 정확히 "(장학)"·"[발전기금]"), 대상 표시("[학부]", "[대학원]", "재학생" …)
     - 목적에 따라 다름: 학교 부서("[도서관]", "[생활협동조합]", "(GTM전공)", "[국제대학]"). 크롤러 재게시 판정은 지우고, **이벤트 묶기는 남긴다** (크롤러의 `drop_units=False`). 기관만 다르고 제목이 같은 국가근로장학생 모집이 많고, 재게시는 `duplicate_of`로 이미 걸러졌기 때문이다.
     - 항상 남김: 재단·장학회·협회 이름, 희망사다리·유형·N차·금액, 과목·분야("(수학)"), 모르는 내용
     - 괄호를 통째로 지우면 "튜터 장학생(한국어)"와 "튜터 장학생(수학)"이 같은 이름이 되고(6개월 데이터에서 실제로 잘못 묶였다), "[대림수암장학문화재단] 장학생"은 "장학생"만 남는다. "[학부]"를 남기면 같은 대림수암 공지가 "[학부]" 유무로 갈린다.
   - 연도·학기·차수, 공지 종류 말("선발, 모집, 신청, 결과, 안내, 공고, 연장, 마감, 지급" …), 공백·기호를 지운다.
   - 비슷한 이름(유사도)으로는 묶지 않는다. "(한국어)"와 "(수학)"처럼 한두 글자 차이가 다른 장학금이다.
2. 연도·학기: 둘 다 있으면 같아야 한다. 한쪽이 모르면 넘어간다.
3. 차수: 같아야 한다. **모름과 2차는 다르다.**
4. 이벤트 첫 공지와 게시일이 120일 이내.

**묶는 순서**: 공지를 게시일 순서로 본다.
- **모집 공지는 항상 새 이벤트를 연다.** 마감된 모집 공지(라벨 `완료`, `notice_kind` `모집`)도 모집 공지라서 새 이벤트를 연다. 같은 이름의 모집 공지가 또 오면 다음 차수나 재모집일 수 있어서다 (실제 예: 장애학생 봉사유형 국가근로장학생 10/8, 11/4 모집).
- 수정 공지와 결과 공지는 같은 장학금인 이벤트 중 가장 최근 것에 붙는다. 없으면 혼자 이벤트가 된다.
- 사슬처럼 이어 묶지 않는다 (항상 이벤트의 첫 공지와 비교).

## 묶음 검수 (`data/reviewed/events.json`)

```json
{
  "labels": { "896003": "수정" },
  "merge": [["895588", "897654"]],
  "split": ["896084"]
}
```

| 키 | 뜻 |
|---|---|
| `labels` | 공지 라벨을 고친다 (`모집` / `수정` / `완료`). `null`이나 다른 값을 적으면 그 공지는 이벤트에 들어가지 않는다 |
| `merge` | 목록 하나에 적은 공지들이 든 이벤트를 하나로 합친다 |
| `split` | 그 공지를 이벤트에서 떼어 혼자 이벤트로 만든다 |

- 공지 하나의 값(마감일, 제외 등)은 지금처럼 `data/reviewed/{bidx}.json`에 적는다. 재게시 표시를 풀거나 붙이는 것도 거기서 `duplicate_of`로 한다.
- `_`로 시작하는 키는 메모다.

## 안전장치

데모 화면이 깨지지 않게 한다.
- 묶기 규칙이나 묶음 검수 적용에서 오류가 나면 경고를 출력하고 **공지 1건 = 이벤트 1개**로 내보낸다 (`grouped_by: "single"`).
- 이벤트 하나를 만들다 오류가 나면 그 묶음만 공지별 이벤트로 내보낸다.
- 정보가 부족한 공지(이름이 짧거나 없음, 차수가 다름)는 묶지 않으므로 혼자 이벤트가 된다.

### 6개월 시험 데이터 (`data/raw_test` 238건, 2026-11-14)

분류 추출(`classifier/extract.py`의 함수)을 스크래치 폴더에 돌린 뒤 `--extracted 폴더 --no-review`로 빌드했다. 재게시를 뺀 219건 중 라벨이 있는 174건 → 이벤트 158개, 2건 이상 묶인 것 5개.

확인 방법
- **잘못 묶인 것**: 2건 이상 묶인 묶음을 전부 제목으로 확인했다.
- **놓친 것**: 혼자 남은 수정·완료 공지 전부와, 이름 유사도 0.6 이상인 다른 이벤트 쌍(모집끼리는 0.9 이상)을 제목으로 확인했다. 이 두 방법에 안 걸리는, 이름이 완전히 다르게 적힌 같은 장학금은 놓쳤을 수 있다.

| | 괄호를 모두 지우던 규칙 | 지금 규칙 |
|---|---|---|
| 잘못 묶임 | 1 (튜터 장학생 "(한국어) 모집"에 "(수학) 추가 모집"이 붙음) | 0 |
| 놓침 | 4 | 3 |

크롤러 목록에 맞춘 뒤(`4353de8` 기준)에도 묶음과 혼자 남은 공지가 위와 같다. 대상 표시("[학부]")를 지우기 전에는 대림수암 "(수정)" 공지가 다시 놓쳐 4건이었다.

- 고쳐진 놓침: 대림수암장학문화재단 "(수정)" 공지가 같은 재단의 연장·추가 선발 공지와 묶였다. "(수학) 추가 모집"은 "(수학) 모집"에 붙었다.
- 남은 놓침 3건은 이름이 다르게 적힌 결과 공지다. 규칙으로 묶으면 다른 재단 결과까지 붙을 위험이 커서 **묶음 검수로 고친다.**
  - 에스엘이충곤재단 장학생 선발 → "장학사업 심사 결과 및 지급 일정 지연" (검수에 넣음)
  - 산업공학과 동문회 선순환 인재 장학금 → "선순환 장학금 장학생 선발 결과" (검수에 넣음)
  - 순득장학재단 "제23기 장학생 추천 신청(수정 3차)" → "2026년 순득장학재단 장학생 선발 결과" (6개월 데이터에만 있음. 이름에 "추천"이 더 있고 차수가 한쪽에만 있음)
- 혼자 남은 결과 공지 대부분(국가장학금 지급 완료 등)은 모집 공지가 교내 게시판에 없거나 수집 기간 밖이라 짝이 없는 것이 맞다. 결과만 있는 이벤트는 화면에 내보내지 않는다.
- 같은 이름의 모집 공지끼리(기관마다 다른 국가근로장학생 모집, 1차·2차 신청 등)는 규칙대로 따로 이벤트가 됐다.
