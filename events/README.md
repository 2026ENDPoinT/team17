# events: 장학금 이벤트 묶기 (화면용 최종 빌드)

같은 장학금에 대한 공지들(모집 → 기한 연장·일정 변경 → 마감·결과)을 **이벤트 하나**로 묶어 화면이 읽을 `web/public/events.json`을 만든다.

- 담당: 크롤링 담당 (이 폴더는 이벤트 묶기 담당만 고친다)
- 입력: `data/extracted/{bidx}.json` (분류 담당), `data/reviewed/{bidx}.json` (공지별 검수), `data/reviewed/events.json` (묶음 검수)
- 출력 형식: [`data/events.sample.json`](../data/events.sample.json). 필드를 바꾸면 샘플과 이 문서를 같이 고치고 화면 담당에게 알린다.

## 실행

```bash
uv run python classifier/extract.py   # data/raw → data/extracted (분류 담당 단계)
uv run python events/build.py         # data/extracted + data/reviewed → web/public/events.json
```

| 파일 | 역할 |
|---|---|
| `group.py` | 묶기 규칙 (순수 함수): 공지 라벨 정하기, 장학금 이름·연도·학기·차수 뽑기, 같은 장학금 판단, 묶기 |
| `build.py` | 단계 연결: 입력 읽기 → 재게시 정리 → 라벨 → 묶기 → 묶음 검수 적용 → 이벤트 만들기 → 저장. 안전장치도 여기 있다 |

## 이벤트 항목 (`items[]`)

`data/scholarships.sample.json` 항목의 필드를 모두 가지고(화면 코드를 거의 그대로 쓸 수 있게), 아래가 더 있다.

| 필드 | 설명 |
|---|---|
| `id` | `event-{첫 공지 bidx}` |
| `status` | 마지막 공지의 라벨: `모집` / `수정` / `완료` |
| `grouped_by` | `auto`(규칙으로 묶음) / `reviewed`(묶음 검수로 바뀜) / `single`(공지 1건뿐이거나 안전장치) |
| `notices` | 이 장학금의 공지 목록, 게시일 순. `{bidx, label, title, board, url, posted_at, also_posted_bidx}` |

이벤트의 값을 정하는 규칙
- **상세 값**(금액·조건·서류·요약·유형·중복 제한): 가장 최근 모집·수정 공지의 값. 비어 있으면 그 앞 공지 값으로 채운다. `title`, `source`(원문 링크)도 가장 최근 모집·수정 공지다.
- **마감일**: 마감일이 있는 가장 최근 모집·수정 공지의 것. 게시일보다 앞선 마감일은 잘못 뽑은 값으로 보고 건너뛰고 `needs_check`에 `deadline`을 넣는다 (실제 예: 896003 "(수정)" 공지에서 `2025-10-05`가 뽑힘).
- **`closed`**: 상태가 `완료`이거나, 가장 최근 모집·수정 공지가 마감 표시("(마감)" 등)면 `true`.
- **재게시**: 크롤러가 `duplicate_of`를 붙인 글은 대표 글과 같은 글이다. 따로 이벤트가 되지 않고 대표 글의 `also_posted_bidx`에 번호만 남는다. 이벤트의 `also_posted_bidx`는 모든 공지의 것을 모은 것이다.
- **모집·수정 공지가 없는 이벤트**(결과 공지만 있는 것)는 내보내지 않는다. 라벨이 없는 공지(안내, 확인필요)도 넣지 않는다.

## 라벨과 묶기 규칙 (`group.py`)

**입력 약속 (분류 담당과 맞추는 중, 2026-11-13).** 분류 출력에 공지마다 아래 필드가 들어오면 그대로 쓰고, 없으면 오른쪽 방법으로 대신 읽는다.

| 필드 | 값 | 없을 때 |
|---|---|---|
| `label` | `모집` / `수정` / `완료` / `null`(이벤트에 넣지 않음) | `notice_kind`가 `결과` → 완료. `모집`이고 제목에 "연장, 수정, 변경, 추가 선발, 추가 모집, 재공지"가 있으면 수정, 아니면 모집. 그 외 → `null` |
| `year` | 2026 같은 정수 | 이름·제목의 "2026학년도", "2026년", "2026-2학기", "26년" |
| `semester` | 1 / 2 | "2학기", "상반기"(1), "하반기"(2) |
| `round` | 차수 정수 (1차, 제7회, 제22기) | 이름의 "2차", "제7회", "제22기" |
| `name` | 장학금 이름 (이미 있음) | 제목 |

**같은 장학금 판단** (이벤트의 첫 공지와 비교)
1. 이름: 괄호 안, 연도·학기·차수, 공지 종류 말("선발, 모집, 신청, 결과, 안내, 공고, 연장, 마감, 지급" …), 공백·기호를 지운 이름이 같거나 유사도 0.9 이상. 지운 이름이 4자 미만이면 판단하지 않는다 ("[대림수암장학문화재단] 2026년 장학생 선발"은 "장학생"만 남아 묶지 않음).
2. 연도·학기: 둘 다 있으면 같아야 한다. 한쪽이 모르면 넘어간다.
3. 차수: 같아야 한다. **모름과 2차는 다르다.**
4. 이벤트 첫 공지와 게시일이 120일 이내.

**묶는 순서**: 공지를 게시일 순서로 본다.
- **모집 공지는 항상 새 이벤트를 연다.** 같은 이름의 모집 공지가 또 오면 다음 차수나 재모집일 수 있어서다 (실제 예: 장애학생 봉사유형 국가근로장학생 10/8, 11/4 모집).
- 수정·완료 공지는 같은 장학금인 이벤트 중 가장 최근 것에 붙는다. 없으면 혼자 이벤트가 된다.
- 사슬처럼 이어 묶지 않는다 (항상 이벤트의 첫 공지와 비교).

## 묶음 검수 (`data/reviewed/events.json`)

```json
{
  "labels": { "896003": "수정" },
  "merge": [["895588", "897654"]],
  "split": ["896084"]
}
```

| 키 | 뜻 |
|---|---|
| `labels` | 공지 라벨을 고친다 (`모집` / `수정` / `완료`). 다른 값을 적으면 그 공지는 이벤트에 들어가지 않는다 |
| `merge` | 목록 하나에 적은 공지들이 든 이벤트를 하나로 합친다 |
| `split` | 그 공지를 이벤트에서 떼어 혼자 이벤트로 만든다 |

- 공지 하나의 값(마감일, 제외 등)은 지금처럼 `data/reviewed/{bidx}.json`에 적는다. 재게시 표시를 풀거나 붙이는 것도 거기서 `duplicate_of`로 한다.
- `_`로 시작하는 키는 메모다.

## 안전장치

데모 화면이 깨지지 않게 한다.
- 묶기 규칙이나 묶음 검수 적용에서 오류가 나면 경고를 출력하고 **공지 1건 = 이벤트 1개**로 내보낸다 (`grouped_by: "single"`).
- 이벤트 하나를 만들다 오류가 나면 그 묶음만 공지별 이벤트로 내보낸다.
- 정보가 부족한 공지(이름이 짧거나 없음, 차수가 다름)는 묶지 않으므로 혼자 이벤트가 된다.

## 실행 결과 (본부 + 학과·취업정보 게시판 71건, 2026-11-13)

- 이벤트 46개. 공지 2건 이상 묶인 것 4개: 생활비 지원 장학금(모집 → 결과, 자동), 발전기금 특정장학금(모집 → "(수정)", 자동), 에스엘이충곤재단(→ 심사 결과, 검수), 산업공학과 동문회 선순환 장학금(→ 선발 결과, 검수). 재게시 4묶음은 `also_posted_bidx`로 들어갔다.
- 안전장치로 내보내면 47개 (분류 빌드의 모집 47건과 같음). 묶이면서 모집 공지 1건(896003)이 앞 공지 이벤트로 들어가 1개 줄었다.
- 알려진 한계: 분류가 뽑은 `name`에 괄호 속 재단 이름이 빠진 경우가 있어("[대림수암장학문화재단] 2026년 장학생 선발" → "2026년 장학생 선발") 그 모집과 "추가 선발" 공지(896084)가 안 묶인다. 이름이 크게 다른 결과 공지도 안 묶인다. 둘 다 묶음 검수로 고친다.
