# 장학금 헌터: 위험 요소와 대응 (해커톤 기준)

> 작성일: 2026-11-13 (해커톤 15시간 기준으로 줄임)
> 데모 범위와 일정은 [scholarship-mvp.md](scholarship-mvp.md), 해커톤 조건은 [AGENTS.md](../AGENTS.md)를 따른다.
> 근거: 게시판 136개의 30일치 목록 실측, 장학금 관련 공지 76건의 본문 분석. ([research-findings.md](research-findings.md) 6절)
> 확인 수준: **직접 확인** / **추정**

## 한눈에 보기

가장 큰 위험은 **데이터를 제때 채우지 못하는 것**이다.

1. **금액이 공지 본문에 거의 없다.** 본문에 금액이 있는 공지는 24%다. 80%에 첨부가 있으니, 금액은 대부분 HWP·PDF 안에 있다고 봐야 한다. (본문은 직접 확인, 첨부 안은 추정)
2. **금액끼리 바로 비교할 수 없다.** 일시금, 등록금 비율, 시급이 섞여 있다. (직접 확인)
3. **"가성비"의 분모를 알 수 없다.** 경쟁률은 공개되지 않는다. 우리가 정의를 정하고 화면에 공개해야 한다. (추정)
4. **15시간 안에 동작하는 데모가 나와야 한다.** 기능을 넓히면 아무것도 끝나지 않는다.

따라서 **자동 추출 + 사람 검수로 20~30건을 확실하게 채우고, 그 데이터로 비교 화면을 완성하는 것**이 목표다.

## 1. 데이터 위험 (가장 중요)

| 위험 | 근거 | 대응 |
|---|---|---|
| **금액·조건이 첨부 안에 있다** | 장학금 공지의 80%에 첨부가 있다. PDF 58개, HWP 55개, HWPX 7개다. 신청서·동의서 양식도 섞여 있다(양식 30개, 공고문 39개). | 파일 이름으로 공고문만 고른다. PDF는 자동 추출을 시도하고, **HWP는 사람이 열어서 입력**한다. 20~30건이면 2명이 2~3시간에 할 수 있다. |
| **LLM이 금액을 지어낸다** | 원문에 없는 숫자를 만들 수 있다. | 추출값마다 근거 문장을 저장하고, 근거 문장에 그 숫자가 실제로 있는지 코드로 확인한다. 최종값은 사람이 확인한다. |
| **신청할 수 없는 공지가 섞여 있다** | 결과 발표, 지급 완료, 등록금 납부 안내도 키워드에 걸린다. | `모집`만 비교표에 넣는다. |
| **같은 장학금이 여러 번 나온다** | 가족장학생 공지는 학과 8곳 이상에 다른 제목으로 올라왔다. 학과 재게시는 새 `bidx`를 받는다. | 데모 데이터에서는 사람이 묶는다. 자동 묶기는 "제목 정규화 + 유사도" 정도로만 보여 준다. |
| **열려 있는 장학금이 적다** | 30일 동안 서로 다른 장학금은 약 56종이다. 지금은 학기 중간이라 모집 중인 것이 적을 수 있다. | 지난 1~2개월 공지까지 포함해 데모 데이터를 만든다. "모집 중만 보기" 필터로 현재 상태도 보여 준다. |
| **마감일 형식이 제각각이다** | "~11/12 18시까지", "2026. 10. 23.~11. 6.", "(마감)" 등. | 데모 데이터는 사람이 날짜 형식으로 고친다. 자동 파싱은 일반적인 형식만 처리한다. |

## 2. 설계 위험

| 위험 | 근거 | 대응 |
|---|---|---|
| **금액 단위가 섞여 있다** | 일시금, 등록금 비율, 시급, "예산 범위 내". | 금액 유형을 필드로 두고, 금액 정렬은 같은 유형끼리만 한다. "등록금 50%"는 원화로 바꾸지 않고 %로 표시한다. |
| **가성비 정의** | 경쟁률을 알 수 없다. | **금액 ÷ 준비 부담**(서류 수, 면접 여부)처럼 단순하게 정하고 계산식을 화면에 보여 준다. "선발 가능성은 반영하지 않음"을 적는다. |
| **필터가 받을 수 있는 장학금을 숨긴다** | 조건이 애매한 공지가 많다("성적 우수자", "가계 곤란"). | 애매한 조건은 숨기지 않고 "조건 확인 필요"로 표시한다. |
| **중복 수혜 제한** | 장학금 공지의 21%에 중복 수혜 관련 문구가 있다. | 카드에 "중복 수혜 제한 있음" 표시만 한다. |
| **학생 정보는 민감하다** | 소득, 장애 여부는 민감하고, 장애 여부는 개인정보보호법상 민감정보다. | 필터 입력은 브라우저 안에서만 쓰고 서버로 보내지 않는다. 데모에서는 학년·학과·유형 필터면 충분하다. |
| **공지 속 개인정보** | 선발 결과에는 마스킹된 이름 명단이 있고, 본문의 16%에 이메일이 있다. | 본문 전체를 보여 주지 않고 추출한 항목과 원문 링크만 보여 준다. |

## 3. 해커톤 진행 위험

| 위험 | 대응 |
|---|---|
| **범위가 커져서 아무것도 안 끝남** | [scholarship-mvp.md](scholarship-mvp.md) 3절의 "만들지 않는다" 목록을 지킨다. AGENTS.md에도 "범위를 넓히지 않는다"를 넣었다. |
| **10:00 직전 푸시 실패** | 동작할 때마다 푸시하고, 최종 푸시는 09:30에 한다. 푸시 시각은 GitHub 서버 기준이다. |
| **팀원이 각자 다른 데이터 형식으로 작업** | 19~20시에 장학금 1건의 필드를 합의하고, 그 형식의 샘플 JSON을 저장소에 먼저 올린다. |
| **AI가 짠 코드를 아무도 설명 못 함** | "구조 이해"가 25점이고, 동점일 때도 이 점수로 가린다. 07시 이후 팀원 모두가 구조도 1장을 보고 데이터 흐름을 말할 수 있게 연습한다. |
| **데모 중 학교 서버가 느리거나 막힘** | 데모는 저장된 데이터로 하고, 실시간 수집은 녹화나 저장된 실행 결과로 보여 준다. |
| **개발 중 학교 서버에 요청이 몰림** | 수집은 한 사람이 한 번 돌려서 결과(JSON)를 저장소에 올리고, 나머지는 그 파일로 개발한다. 같은 호스트에는 요청 간격 1초 이상. |
| **크롤링 함정** | 페이지 이동은 `nowpage`가 아니라 `page`다. 목록 레이아웃은 표형과 카드형 두 가지다. 새 글 판정은 "처음 보는 `bidx`"로 한다. ([AGENTS.md](../AGENTS.md) "학교 사이트" 절) |
| **사전 작업 규정** | 캡스톤 작품과 겹치면 실격될 수 있다. 행사 전에 만든 `tools/research/` 스크립트는 써도 된다고 운영진에게 확인받았다(2026-11-13). |
| **리뷰 없이 합치다 충돌** | PR 리뷰를 필수로 하지 않기로 했다. 푸시 전 `git pull --rebase`, 파일 담당 나누기, `--force` 금지로 막는다. (AGENTS.md "작업 방식") |

## 4. 발표 Q&A에서 나올 만한 질문

| 질문 | 준비할 답 |
|---|---|
| 공식 앱과 뭐가 다른가? | 공식 앱은 본부 장학 공지를 보여 준다. 우리는 학과 게시판까지 모으고(장학금의 70%가 본부 장학공지 밖에 있었다), 금액·조건을 비교·정렬한다. |
| 금액은 어떻게 뽑았나? | 본문·PDF는 LLM으로 후보를 뽑고 근거 문장을 확인한다. HWP는 아직 사람이 입력한다. 다음 단계는 HWP 자동 추출이다. |
| 가성비는 어떻게 계산하나? | 계산식을 그대로 설명한다. 선발 가능성은 반영하지 않는다고 말한다. |
| 학교 사이트를 크롤링해도 되나? | robots.txt가 없고(70개 호스트 중 69개), 요청 간격을 두고, 본문을 복제하지 않고 원문 링크로 보낸다. 정식 운영 전에는 학교와 협의할 계획이다. |
| 정보가 틀리면? | 모든 항목에 원문 링크와 "공식 공지 확인" 안내를 붙였다. 정식 운영 때는 수정 감지와 오류 신고를 넣는다. |
