## 1. 한 줄 정의

서울과기대 교내 게시판(본부·학과)에 흩어진 **장학금 공지를 모아, 금액·조건·마감을 한 표로 비교하고 정렬·필터할 수 있게** 해 주는 서비스.

## 2. 발표에 쓸 문제 근거 (직접 확인한 실측)

심사 항목 "문제 정의"는 근거를 본다. 아래 숫자는 2026-10-14 ~ 11-13 데이터에서 직접 센 것이다.

| 근거 | 숫자 |
|---|---|
| 장학금 공지가 흩어져 있다 | 30일 동안 장학금 관련 공지 **76건이 31개 게시판**에 올라왔다. 본부 장학공지에는 23건(**30%**)뿐이다 |
| 학과에만 올라온 장학금이 있다 | 전기공사공제조합장학회(전기정보공학과), 산업보건분야 장학생(안전공학과), 덕신EPC 건축안전 장학생(건축공학전공) |
| 같은 공지가 여러 번 올라온다 | 가족장학생 공지가 학과 8곳 이상에 다시 올라왔다 |
| 비교가 어렵다 | 본문에 금액이 적힌 공지는 **24%**, 첨부(HWP·PDF)가 있는 공지는 **80%**다. 금액을 보려면 파일을 하나하나 열어야 한다 |
| 금액 형식이 제각각이다 | "등록금 50% 감면", "250만원", "시급 10,320원", "등록금 전액"이 섞여 있다 |

공식 스마트캠퍼스 앱도 장학 공지를 보여 주지만, 학과 게시판 통합과 금액·조건 비교는 하지 않는다. 그것이 우리 차별점이다. (앱의 실제 범위는 미확인)

## 3. 데모 범위

### 만든다 (데모에서 끝까지 동작해야 하는 흐름)

1. **수집**: 본부 장학공지 + 장학금이 올라오는 학과 게시판에서 제목 키워드("장학", "근로", "학자금", "등록금")로 장학금 공지를 모은다. 첨부 PDF·HWP·HWPX·DOCX의 텍스트도 뽑는다 (2026-11-13 구현. 결과 공지의 첨부는 명단 때문에 뽑지 않는다).
2. **정리**: 공지마다 아래 항목을 채운다. 자동 추출(본문·PDF, LLM 보조)한 뒤 **팀원이 확인해서 고친다.**
   - 장학금 이름, 유형(교내 / 교외 재단·지자체 / 근로), 금액과 금액 유형(일시금 / 등록금 비율 / 시급), 마감일
   - 대상 조건: 학년, 학과, 성적, 소득, 거주지 (확실한 것만, 애매하면 "확인 필요")
   - 준비 부담: 서류 종류, 면접 여부
   - 원문 링크, 중복 수혜 제한 여부
3. **비교 화면**: 장학금 카드 또는 표
   - 정렬: **마감 임박 순**, **금액 순**(같은 금액 유형끼리), **가성비 순**(금액 ÷ 준비 부담, 계산식을 화면에 표시)
   - 필터: 유형, 학년, 학과, 모집 중만 보기
   - 모든 항목에 **원문 링크**와 "공식 공지를 확인하세요" 안내

### 만들지 않는다 (발표에서 "다음 단계"로만 말한다)

- 알림(푸시, 이메일, 봇)
- 회원가입, 로그인, 서버에 저장하는 사용자 프로필
- 포스터 이미지 인식
- 실시간 자동 수집 스케줄러 (데모에서는 수집 스크립트를 한 번 돌린 결과를 쓴다)
- 교외 사이트(한국장학재단, 지자체, 재단) 직접 수집

### 데모 데이터

- 최근 1~2개월 장학금 공지에서 **모집 공지 20~30건**을 골라 팀원이 검수한 데이터로 시연한다.
- 결과 발표, 지급 완료, 등록금 납부 안내는 비교 대상에서 뺀다.
- 실제 학교 서버에서 수집하는 장면은 "수집 스크립트 실행 → 새 공지가 목록에 들어온다" 정도로 짧게 보여 준다. 학교 서버가 느리거나 막힐 수 있으니 **녹화나 저장된 결과를 준비해 둔다.**

### 데이터 흐름과 역할 (2026-11-13 결정, 3명)

```
[크롤링 담당]  crawler/    ──> data/raw/{bidx}.json         공지 원본: 제목, 날짜, 게시판, 원문 링크, 본문·첨부 텍스트(개인정보 제거), 해시
                                                            내용이 같은 복사본(재게시)만 duplicate_of로 표시
[분류 담당]    classifier/ ──> data/extracted/{bidx}.json   공지마다 추출: 유형, 금액, 조건, 마감, 서류·면접
                                                            + 라벨: 모집 / 수정(기한 연장·일정 변경) / 완료(마감·결과)
               사람 검수   ──> data/reviewed/{bidx}.json    틀린 값 고치기 (공지별)
[이벤트 묶기]  events/     ──> web/public/events.json       같은 장학금의 공지들(모집 → 수정 → 완료)을 이벤트 1개로 묶음 (최종 빌드)
                                                            마감일은 마지막 수정 공지, 상태는 마지막 공지 기준
               사람 검수   ──> data/reviewed/events.json    틀린 묶음 고치기 (라벨, 묶기, 떼기)
[화면 담당]    web/        <── events.json을 읽어 정렬·필터·가성비 계산 (logic.js). 카드 1개 = 이벤트 1개
```

**"같은 공지"를 두 층으로 나눈다** (2026-11-13 결정)
- **같은 게시물(재게시)**: 학과가 본문·첨부를 그대로 복사해 다시 올린 글. 사실의 문제라 **크롤러**가 표시한다. 잘못 묶으면 장학금이 숨으므로 내용이 같을 때만 표시한다 (`crawler/README.md` "재게시 묶기").
- **같은 장학금 이벤트**: 모집 공지, 기한 연장, 마감, 선발 결과처럼 같은 장학금에 대한 다른 공지. 장학금 이름·차수·라벨을 알아야 하므로 **라벨링 다음 단계(이벤트 묶기)**가 묶는다.
- 이벤트 묶기는 `events/`, 출력은 `web/public/events.json`이고, **화면용 최종 빌드는 이벤트 묶기가 한다** (2026-11-13 결정). 분류의 `scholarships.json`(공지 단위)은 분류 확인용으로 남는다. 규칙과 안전장치는 `events/README.md`.
- 잘못 묶으면 장학금 하나가 화면에서 숨으므로 **애매하면 묶지 않는다.** 묶기가 실패하면 공지 1건 = 이벤트 1개로 내보내 화면이 깨지지 않게 한다.
- 분류 출력에 공지마다 `label`(모집/수정/완료), `year`, `semester`, `round`(차수)를 넣어 주기로 분류 담당과 맞춘다 (2026-11-13 요청). 들어오기 전까지 이벤트 묶기는 `notice_kind`와 제목으로 대신 읽는다.

| 역할 | 폴더 (이 사람만 고침) | 만들어 넘기는 것 | 받는 것 |
|---|---|---|---|
| **화면** | `web/` | 데모 화면 | `web/public/events.json` (이벤트 단위) |
| **크롤링** | `crawler/`, `data/raw/` | 공지 원본 JSON. PDF·HWP 첨부는 **텍스트만** 뽑아 넣고 파일은 저장하지 않는다. 이메일·전화번호·이름 명단은 이 단계에서 지운다 | 게시판 목록 (`tools/research/boards.txt` 출발점) |
| **분류** | `classifier/`, `data/extracted/` | 공지마다 추출값과 라벨(모집/수정/완료) | `data/raw/` |
| **이벤트 묶기** (크롤링 담당이 이어서) | `events/` | 화면용 `web/public/events.json` | `data/extracted/`, `data/reviewed/` |
| 검수 (모두) | `data/reviewed/` | 사람이 고친 값 | – |

**서로 기다리지 않기 위한 약속**
- 시작 1시간 안에 **샘플 파일 2개**를 먼저 커밋한다. 실제 데이터가 나오기 전까지 각자 이 샘플로 개발한다.
  - 크롤링 담당: `data/raw/_sample.json` (분류 담당이 받음)
  - 분류 담당: `data/scholarships.sample.json` (공지 1건의 필드)
  - 이벤트 묶기: `data/events.sample.json` (화면 담당이 받음. 항목 = 이벤트, 필드는 위 샘플 + `status`, `notices`)
- 필드를 바꾸면 **샘플도 같이 고치고 팀에 알린다.** 상대 폴더의 코드는 고치지 않는다.
- 가성비 **입력값**(금액, 서류 수, 면접 여부)은 분류 담당이 채우고, **계산식**은 화면의 `logic.js` 함수 하나에 둔다. 계산식은 데이터를 보고 둘이 함께 정한다.
- 검수는 분류 담당이 주로 하고, 02:00 이후에는 셋이 나눠서 한다.

- 장학금 수십 건 규모라 DB가 필요 없다. 정렬·필터는 브라우저에서 한다.
- 크롤러와 사람이 고치는 폴더를 나눠, 정기 수집(GitHub Actions 자동 커밋)을 붙여도 충돌이 나지 않게 한다.
- 데모는 크롤러를 한 번 돌린 결과로 한다. 정기 실행은 시간이 남으면 붙인다. (GitHub Actions 해외 IP 접근은 먼저 테스트)
- DB는 사용자별 데이터나 웹 검수 화면이 필요해질 때 다시 검토한다.

## 5. 개인정보 원칙 (짧게)

- 학생 정보(학년, 학과, 소득 등)는 **서버에 보내지 않는다.** 필터는 브라우저 안에서만 한다.
- 공지 본문 전체를 다시 보여 주지 않는다. 이름 명단, 이메일, 전화번호는 화면에 내지 않는다.
- 첨부파일은 저장·재배포하지 않고 원문 링크로 보낸다.
