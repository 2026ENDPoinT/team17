# 장학금 헌터 MVP 범위

> 작성일: 2026-11-13
> 관련 문서: [project-risks.md](project-risks.md) (위험 요소와 대응) · [research-findings.md](research-findings.md) · [notice-sources.md](notice-sources.md)
>
> **주의**: 아래 3절 단계 계획은 첨부 분석을 v3에 두었다. 하지만 금액·조건 비교가 핵심 기능이면 첨부 분석이 앞당겨져야 한다. 장학금 공지의 80%에 첨부가 있고, 본문에 금액이 있는 글은 24%뿐이다. ([project-risks.md](project-risks.md) 3절)

## 1. 결정 사항

| 항목 | 결정 (2026-11-13) |
|---|---|
| 서비스 | **장학금 헌터**: 서울과기대 학생에게 해당되는 장학금 공지를 찾아 주고 마감 전에 알려 준다 |
| 수집 범위 | **교내 게시판에 올라온 공지만** 수집한다. 학교가 대신 홍보하는 교외 장학금("(홍보)" 공지)은 교내 게시판에 올라오므로 포함된다 |
| 제외 | 한국장학재단, 지자체, 재단 사이트를 직접 수집하는 것은 하지 않는다. 확장 가능성이 보이면 나중에 검토한다 |
| 진행 방식 | 작게 만들어 보고 단계적으로 넓힌다 (3절) |

기존 문서들은 "공지 전체 모아보기"를 전제로 썼다. 사이트 구조, 크롤링 방법, 법·개인정보 원칙은 그대로 적용된다. **서비스 범위와 우선순위는 이 문서가 기준이다.**

## 2. 장학금 공지 실측 (직접 확인)

2026-10-14 ~ 11-13 수집 데이터에서 제목에 "장학", "등록금", "학자금", "근로"가 들어간 글을 다시 셌다. ([research-findings.md](research-findings.md) 6절과 같은 데이터)

| 항목 | 값 |
|---|---|
| 30일 동안 올라온 장학금 관련 글 | **76건** (`bidx` 기준), 그중 대학원 게시판에만 있는 글 13건 |
| 글이 올라온 게시판 수 | **31개** |
| 본부 장학공지 비중 | 23건 (30%) |
| 본부 게시판에 없는 글 | 50건 (같은 공지의 학과 재게시 포함) |
| 제목에 마감 표현이 있는 글 | 25건 (33%) |

**유형별 분포** (제목 기준 대략 분류)

| 유형 | 건수 | 예 |
|---|---|---|
| 교내 장학 선발 | 41 | 어의장학생, SeoulTech 가족장학생, 학석사연계과정 장학금 |
| 교외 (재단·지자체) 홍보 | 13 | 유하푸른재단, 통영시 저소득 대학생, 강화군 등록금 지원, 전기공사공제조합장학회 |
| 근로장학 | 8 | 국가근로 교체선발, 학과사무실 근로장학생 |
| 결과·지급 안내 | 6 | 국가장학금 후지급 완료, 장학생 선정 결과 |
| 등록금 납부·지원 | 4 | 등록금 분할납부 안내 |
| 국가장학·한국장학재단 | 4 | 중복지원 방지 사업 안내 |

**학과 게시판에만 올라온 장학금이 있다.** 본부 장학공지만 보면 놓친다.
- 전기정보공학과: 전기공사공제조합장학회 장학생 선발 (~11.13)
- 안전공학과: 산업보건분야 미래인재 양성사업 장학생
- 건축공학전공 (장학금 게시판): 덕신EPC 건축안전 장학생
- 여러 학과: 학과사무실 근로장학생 모집

**시사점**
- 한 달에 수십 건이라 "모아보기"만으로는 차별화가 약하다. 가치는 **"나한테 해당되는 것만"과 "마감 전에"**에서 나온다.
- 같은 장학금이 본부와 여러 학과에 다른 제목으로 올라온다. 예: 본부의 "(통정시 신청, 2026. 10. 23.~11. 6.) 2026. 2학기 2차 어의 및 가족…"과 학과의 "2026학년도 2학기 2차 어의장학생 선발 안내". **중복 묶기가 필수다.**
- "결과·지급 안내"와 "등록금 납부"는 신청할 장학금이 아니다. 따로 분류해서 알림 대상에서 뺄지 정해야 한다.

## 3. 단계별 계획

각 단계를 끝내면 실제 학생 몇 명에게 써 보게 하고 다음 단계를 정한다.

| 단계 | 수집 | 기능 | 확인할 것 |
|---|---|---|---|
| **v0** | 본부 장학공지 1개 게시판 | 장학금 목록, 원문 링크, 제목에서 뽑은 마감일, 마감 임박 순 정렬 | 학생들이 실제로 열어 보는가 |
| **v1** | 활동 중인 학과·지원기관 게시판 전체 (제목 키워드로 장학금만 남김) | 중복 묶기, "내 학과" 필터, 마감 알림 1개 채널 | 학과 게시판에서 찾은 장학금이 의미 있는가 |
| **v2** | 같음 | 자격 태그 추출 (학년, 학과, 지역, 소득 조건, 성적, 대상: 학부/대학원/외국인 등), 자격 필터 | 자격 추출이 얼마나 정확한가 |
| **v3** | 같음 + 첨부 | 첨부(PDF·HWP)와 포스터 이미지에서 자격·마감 추출 | 첨부에만 있는 조건이 얼마나 되는가 |
| 확장 | 한국장학재단·지자체·재단 사이트 | 교외 장학금 직접 수집 | 교내 버전의 반응을 보고 결정 |

> v1의 수집 비용은 v0와 거의 같다. 목록 1페이지만 읽으면 되고, 30일 동안 새 글이 0건인 게시판 57개는 주기를 낮추면 된다. ([research-findings.md](research-findings.md) 6.1절)

## 4. 개인정보 설계 원칙

자격 필터를 하려면 학생의 **학년, 학과, 거주지, 소득분위, 장애 여부** 같은 정보가 필요하다. 그중 건강 정보(장애 여부)는 개인정보보호법상 **민감정보**라서 처리 요건이 훨씬 엄격하다. 소득분위도 노출되면 피해가 크다.

| 원칙 | 방법 |
|---|---|
| 서버에 저장하지 않는다 | 자격 조건은 **사용자 브라우저(또는 앱) 안에만** 저장하고, 필터링도 기기 안에서 한다. 서버는 장학금 목록과 자격 태그만 내려 준다 |
| 꼭 필요한 것만 묻는다 | v1은 학과만 묻는다. 지역·소득은 v2에서 필요할 때 선택 항목으로 넣는다 |
| 알림용 연락처와 자격 정보를 분리한다 | 알림을 보내려고 서버에 연락처를 둬야 한다면, 그 연락처에 학과 정도만 연결하고 소득·장애 정보는 연결하지 않는다 |

공지 본문 처리 원칙(이메일·전화번호·이름 제거, 본문 재게시 금지, 첨부 재배포 금지)은 [AGENTS.md](../AGENTS.md)를 따른다. 장학생 선발 결과 공지에는 마스킹된 이름 명단이 있는 경우가 많으니 특히 주의한다.

## 5. 장학금 공지에서 더 조심할 것

| 위험 | 이유 | 대응 |
|---|---|---|
| 마감일을 잘못 알려 줌 | 장학금은 마감을 놓치면 끝이다. 원망이 서비스로 온다 | 추출한 마감일은 "추정"으로 표시하고 원문 링크를 항상 보여 준다. 공지가 수정되면("기한 연장", "(마감)") 다시 읽어 갱신한다 |
| 자격이 맞는데 숨김 | 자격 추출이 틀리면 학생이 받을 수 있는 장학금을 못 본다. 보여 주는 것보다 숨기는 쪽이 더 큰 손해다 | 애매하면 숨기지 않고 "조건 확인 필요"로 보여 준다 |
| 키워드로 못 잡는 장학금 | 컴퓨터공학과 "취업준비 멘토링2 EPiC 신청(안내-장학금지급)"처럼 장학금이 부수적으로 붙은 프로그램이 있다. 제목에 장학 관련 단어가 없는 글은 이번 집계에서 빠졌을 수 있다 | v1 키워드 목록을 실제 놓친 사례로 계속 보강한다. 필요하면 LLM 분류를 보조로 쓴다 |
