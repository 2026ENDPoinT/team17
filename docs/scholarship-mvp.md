# 장학금 헌터: 해커톤 데모 범위와 15시간 계획

> 작성일: 2026-11-13 (해커톤 15시간 기준으로 다시 씀)
> 해커톤 조건(일정, 제출, 심사)은 [AGENTS.md](../AGENTS.md) "해커톤 조건" 절에 있다.
> 관련 문서: [project-risks.md](project-risks.md) (위험과 대응) · [research-findings.md](research-findings.md) (사이트 기술 사실, 실측) · [notice-sources.md](notice-sources.md) (게시판 URL)

## 1. 한 줄 정의

서울과기대 교내 게시판(본부·학과)에 흩어진 **장학금 공지를 모아, 금액·조건·마감을 한 표로 비교하고 정렬·필터할 수 있게** 해 주는 서비스.

## 2. 발표에 쓸 문제 근거 (직접 확인한 실측)

심사 항목 "문제 정의"는 근거를 본다. 아래 숫자는 2026-10-14 ~ 11-13 데이터에서 직접 센 것이다.

| 근거 | 숫자 |
|---|---|
| 장학금 공지가 흩어져 있다 | 30일 동안 장학금 관련 공지 **76건이 31개 게시판**에 올라왔다. 본부 장학공지에는 23건(**30%**)뿐이다 |
| 학과에만 올라온 장학금이 있다 | 전기공사공제조합장학회(전기정보공학과), 산업보건분야 장학생(안전공학과), 덕신EPC 건축안전 장학생(건축공학전공) |
| 같은 공지가 여러 번 올라온다 | 가족장학생 공지가 학과 8곳 이상에 다시 올라왔다 |
| 비교가 어렵다 | 본문에 금액이 적힌 공지는 **24%**, 첨부(HWP·PDF)가 있는 공지는 **80%**다. 금액을 보려면 파일을 하나하나 열어야 한다 |
| 금액 형식이 제각각이다 | "등록금 50% 감면", "250만원", "시급 10,320원", "등록금 전액"이 섞여 있다 |

공식 스마트캠퍼스 앱도 장학 공지를 보여 주지만, 학과 게시판 통합과 금액·조건 비교는 하지 않는다. 그것이 우리 차별점이다. (앱의 실제 범위는 미확인)

## 3. 데모 범위

### 만든다 (데모에서 끝까지 동작해야 하는 흐름)

1. **수집**: 본부 장학공지 + 장학금이 올라오는 학과 게시판에서 제목 키워드("장학", "근로", "학자금", "등록금")로 장학금 공지를 모은다.
2. **정리**: 공지마다 아래 항목을 채운다. 자동 추출(본문·PDF, LLM 보조)한 뒤 **팀원이 확인해서 고친다.**
   - 장학금 이름, 유형(교내 / 교외 재단·지자체 / 근로), 금액과 금액 유형(일시금 / 등록금 비율 / 시급), 마감일
   - 대상 조건: 학년, 학과, 성적, 소득, 거주지 (확실한 것만, 애매하면 "확인 필요")
   - 준비 부담: 서류 종류, 면접 여부
   - 원문 링크, 중복 수혜 제한 여부
3. **비교 화면**: 장학금 카드 또는 표
   - 정렬: **마감 임박 순**, **금액 순**(같은 금액 유형끼리), **가성비 순**(금액 ÷ 준비 부담, 계산식을 화면에 표시)
   - 필터: 유형, 학년, 학과, 모집 중만 보기
   - 모든 항목에 **원문 링크**와 "공식 공지를 확인하세요" 안내

### 만들지 않는다 (발표에서 "다음 단계"로만 말한다)

- 알림(푸시, 이메일, 봇)
- 회원가입, 로그인, 서버에 저장하는 사용자 프로필
- HWP 자동 추출 (시간이 남으면 시도. 실패하면 사람이 입력)
- 포스터 이미지 인식
- 실시간 자동 수집 스케줄러 (데모에서는 수집 스크립트를 한 번 돌린 결과를 쓴다)
- 교외 사이트(한국장학재단, 지자체, 재단) 직접 수집

### 데모 데이터

- 최근 1~2개월 장학금 공지에서 **모집 공지 20~30건**을 골라 팀원이 검수한 데이터로 시연한다.
- 결과 발표, 지급 완료, 등록금 납부 안내는 비교 대상에서 뺀다.
- 실제 학교 서버에서 수집하는 장면은 "수집 스크립트 실행 → 새 공지가 목록에 들어온다" 정도로 짧게 보여 준다. 학교 서버가 느리거나 막힐 수 있으니 **녹화나 저장된 결과를 준비해 둔다.**

## 4. 15시간 일정 (예시)

| 시간 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 19:00 ~ 20:00 | 스택 결정, 역할 분담, 저장소 세팅, 데이터 형식(장학금 1건의 필드) 합의 | `AGENTS.md` 기술 스택 표 채움, 빈 프로젝트가 팀원 모두의 PC에서 실행됨 |
| 20:00 ~ 23:00 | 수집 스크립트 / 화면 뼈대 / 추출 프롬프트를 **동시에** 진행 | 장학금 공지 목록 JSON이 나옴, 가짜 데이터로 화면이 뜸 |
| 23:00 ~ 02:00 | 추출 → 검수 → 데이터 확정, 화면에 실제 데이터 연결 | 실제 장학금 20건 이상이 화면에 보임 |
| 02:00 ~ 05:00 | 정렬·필터·가성비 계산, 화면 다듬기 | 데모 흐름이 처음부터 끝까지 동작 |
| 05:00 ~ 07:00 | 버그 수정, 처음 보는 사람 시점으로 써 보기 | 팀원 아닌 사람이 설명 없이 사용 가능 |
| 07:00 ~ 09:00 | 발표 자료, 데모 리허설, 구조도 1장, README | 팀원 모두 데이터 흐름을 설명할 수 있음 |
| **09:30** | **최종 푸시** (10:00 직전에 하지 않는다) | GitHub에서 최신 커밋 확인 |

## 5. 개인정보 원칙 (짧게)

- 학생 정보(학년, 학과, 소득 등)는 **서버에 보내지 않는다.** 필터는 브라우저 안에서만 한다.
- 공지 본문 전체를 다시 보여 주지 않는다. 이름 명단, 이메일, 전화번호는 화면에 내지 않는다.
- 첨부파일은 저장·재배포하지 않고 원문 링크로 보낸다.
