# crawler: 교내 게시판 장학금 공지 수집

교내 게시판 목록에서 제목에 장학금 키워드가 있는 글을 골라 상세 페이지를 읽고, 글 1건마다 `data/raw/{bidx}.json` 파일 1개를 만든다.

- 담당: 크롤링 담당 (이 폴더와 `data/raw/`는 크롤링 담당만 고친다)
- 받는 사람: 분류 담당 (`classifier/`가 `data/raw/`를 읽는다)
- 형식의 기준: [`data/raw/_sample.json`](../data/raw/_sample.json). 필드를 바꾸면 샘플과 이 문서를 같이 고치고 팀에 알린다.

## 실행

저장소 루트에서 실행한다. 외부 라이브러리 없이 표준 라이브러리만 쓴다.

```bash
uv run python crawler/crawl.py --mode offline   # 저장된 HTML만 사용 (개발·테스트용, 학교 서버 요청 없음)
uv run python crawler/crawl.py --mode record    # 학교 서버에서 받고, HTML을 crawler/fixtures/에 저장
uv run python crawler/crawl.py --mode live      # 학교 서버에서 받기만
```

- `crawler/fixtures/`는 Git에 올리지 않는다. 원본 HTML에 연락처가 그대로 있기 때문이다. 처음 한 번 `record`로 만든다.
- 게시판 16곳의 최근 60일, 71건을 처음 받는 데 약 2분 30초 걸린다 (2026-11-13). 같은 호스트에는 1초 간격으로 요청한다.
- 이미 받은 글은 최근 14일 안의 글만 다시 읽는다. `content_hash`가 바뀌면 덮어쓰고 `수정됨`으로 출력한다.
- 같은 `bidx`가 두 게시판에 나오면(미러 게시판) `BOARDS`에서 먼저 나온 게시판 것만 저장한다.

| 파일 | 역할 |
|---|---|
| `config.py` | UA, 요청 간격, 키워드, 수집 기간, 게시판 목록 |
| `fetch.py` | HTML 받기 (live / record / offline) |
| `parse.py` | 목록·상세 HTML 파싱 (네트워크 없음) |
| `privacy.py` | 연락처·학번·마스킹된 이름·결과 공지 이름 명단 지우기 |
| `dedup.py` | 재게시 묶기 (`duplicate_of` 정하기, 네트워크 없음) |
| `crawl.py` | 위를 연결해 `data/raw/{bidx}.json` 저장 |

## `data/raw/{bidx}.json` 필드

샘플 값은 **지어낸 예시**다. 실제 공지가 아니다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `_sample` | bool | 샘플 파일에만 `true`. 실제 수집 파일에는 없다. 분류 쪽은 이 값이 있는 파일을 건너뛴다 |
| `bidx` | int | 글 번호. 전역 고유이고 파일 이름으로 쓴다 |
| `bnum` | int | 게시판 번호. 첨부 경로(`/storage/{site}/bbs/{bnum}/…`)에 쓰인다. 샘플은 `0` |
| `site` | string | 호스트 앞부분 (`www`, `ice`, `mech` …). `tools/research/boards.txt` 첫 칸과 같다 |
| `board` | string | 게시판 이름 (`장학공지`, `공지사항` …) |
| `url` | string | 원문 상세 주소. 화면의 "원문 보기" 링크로 쓴다 |
| `title` | string | 목록에 보이는 제목 그대로. "(마감)", "연장" 같은 수정도 그대로 둔다 |
| `posted_date` | string | 게시일 `YYYY-MM-DD`. 사이트에 시각이 없어서 날짜만 있다 |
| `pinned` | bool | 목록 상단 고정 공지인지 |
| `duplicate_of` | int \| null | 다른 게시판에 다시 올린 글이면 **대표 글의 `bidx`**, 대표 글이거나 혼자인 글이면 `null`. 대표 글 기준으로 모으면 분류 쪽 `also_posted_bidx`가 된다. 아래 "재게시 묶기" 참고 |
| `matched_keywords` | string[] | 제목에서 걸린 키워드 (`장학`, `근로`, `학자금`, `등록금`. 취업정보 게시판은 `장학`만). 장학 전용 게시판 글은 비어 있을 수 있다 |
| `body_text` | string | 본문(`td.cont`) 텍스트. 줄바꿈 유지, HTML 태그 제거. **이메일·전화번호(내선·대표번호 포함)는 `[연락처]`, 학번은 `[학번]`, 마스킹된 이름(홍*동)은 `[이름]`, 결과 공지의 이름 나열("선발결과 : 홍길동, 김철수 (이상 2명)")은 `[명단 삭제]`로 바꾼 뒤** 저장한다. 표나 한 줄에 한 명씩 쓴 명단은 못 잡을 수 있다. 본문이 없으면 `""` |
| `has_images` | bool | 본문에 이미지가 있는지. 포스터만 있는 글(본문 `""` + `true`)을 분류 쪽이 "원문 확인 필요"로 넘기는 데 쓴다 |
| `attachments` | object[] | 첨부 목록. 없으면 `[]`. 파일 자체는 저장하지 않는다 |
| `attachments[].name` | string | 화면에 보이는 첨부 이름 |
| `attachments[].ext` | string | 소문자 확장자 (`pdf`, `hwp`, `hwpx` …) |
| `attachments[].url` | string | 원문 첨부 주소 (다시 배포하지 않고 링크만 둔다) |
| `attachments[].text` | string \| null | 첨부에서 뽑은 텍스트 (개인정보 제거 후). 뽑지 않았거나 실패하면 `null` |
| `attachments[].text_status` | string | `ok` / `failed` / `not_extracted` / `unsupported` |
| `content_hash` | string | `sha256:` + `sha256(title + "\n" + body_text)`. 다시 읽었을 때 값이 바뀌면 글이 수정된 것이다 |
| `first_seen` | string | 처음 수집한 시각 (ISO 8601, `+09:00`) |
| `last_checked` | string | 마지막으로 다시 읽은 시각 |

## 실제 수집 결과로 확인한 것 (본부 장학공지 37건, 2026-11-13)

학과 게시판 등 34건을 더한 71건도 모두 샘플과 필드가 같다. 학과 쪽 34건은 본문 100자 미만이 6건(18%)으로 본부보다 적다.

- 37건 모두 샘플과 필드 이름·타입이 같다.
- 본부 장학공지는 하위 게시판 2개(장학공지 `bnum=5233`, 근로장학 `bnum=57138`)를 합쳐 보여 준다. 그래서 `bnum`은 글마다 다르다.
- **본문이 100자 미만인 글이 16건(43%)이다.** 대부분 교외 "(홍보)" 공지이고, 내용은 포스터 이미지(`has_images: true`)나 첨부에 있다. 전체 공지 평균(18%)보다 훨씬 높다. 금액·마감·조건을 뽑으려면 첨부나 이미지를 봐야 하는 글이 많다.
- 첨부가 있는 글은 30건(81%)이다. 형식은 pdf 22, hwp 21, hwpx 7, docx 3, jpg 2, xlsx 1개다.
- 제목에 키워드가 없는 글이 2건 있다 (시험지원인력 모집, 아동돌봄 지원사업). 장학 게시판이라 거르지 않고 넣었다. 장학금인지는 분류 단계에서 판단한다.
- 저장된 본문과 제목에 전화번호·이메일 패턴이 남은 글은 없다. 13건에서 `[연락처]`로 바꿨다.

## 수집 게시판 (`config.BOARDS`, 16곳)

2026-11-13에 게시판 136곳의 최근 60일 목록을 실측해서 골랐다 (`tools/research/volume.py`).

| 구분 | 게시판 | 고른 이유 |
|---|---|---|
| 장학 전용 (키워드로 거르지 않음) | 본부 장학공지, 건축학부 장학금 | 게시판 전체가 장학금 |
| 학부 공지 (제목 키워드로 거름) | 본부 대학공지, 산업공학과, 건설시스템공학과, 전기정보공학과, 지능형반도체공학과, 안전공학과, 안경광학과, GTM전공, 컴퓨터공학과, 경영학전공, 국제대학 | 본부 공지를 다시 올린 것이 아니라 **학과가 직접 올린** 장학금 공지가 있었다 |
| 취업정보 (`장학`만) | 기계·자동차공학과, 기계시스템디자인공학과, MSDE학과 | 기업 연구장학생 모집 (현대모비스 등) |

- **넣지 않은 것**: 대학원 공지 게시판(팀 결정: 학부생 대상), 본부 공지를 다시 올리기만 한 학과 게시판(어의·가족장학생 등이 15곳 이상에 똑같이 올라옴), 학사공지(등록금 납부 안내뿐).
- 학과 게시판을 더 넣으면 재게시가 많아지므로, 아래 재게시 묶기를 먼저 만든다.

## 결과 공지의 이름 명단

산업공학과 "선발 결과 알림"에 마스킹되지 않은 이름 3명이 본문에 있었다. `privacy.py`에 명단 줄 규칙을 넣어 `[명단 삭제]`로 바꿨다. 처음 만든 규칙은 "미선발자", "수혜자는" 같은 일반 문장까지 지워서, 명단 줄 조건을 "선발결과 :", "합격자 명단 :", "(이상 N명)"처럼 좁혔다. 71건 모두 확인했을 때 남은 명단과 잘못 지운 문장은 없었다.

## 재게시 묶기 (`dedup.py`)

학과가 본부·다른 학과 공지를 다시 올리면 `bidx`가 새로 생긴다. 크롤러가 제목으로 묶어 `duplicate_of`에 대표 글 번호를 적는다 (2026-11-13 결정). 파일은 지우지 않는다.

- 수집이 끝날 때마다 `data/raw` 전체를 다시 보고 표시한다.
- 같은 글로 보는 조건: 서로 다른 게시판 / 정규화 제목 유사도 0.9 이상 / 제목 속 숫자가 모두 같음 / 게시일 14일 이내
- 대표 글: 본부(`www`) 글 > 먼저 올라온 글 > `bidx`가 작은 글
- 실제 데이터로 정한 기준이다. 비슷하지만 다른 공지가 있었다.
  - "생활비 지원 장학금 **신청** 안내"와 "**선발 결과** 안내"는 유사도 0.85였다. 그래서 기준을 0.9로 잡았다.
  - "국가장학금 **1차** 지급완료"와 "**2차** 지급완료"는 0.96이었다. 그래서 숫자가 다르면 묶지 않는다.
  - 같은 게시판에 같은 제목이 두 번 올라온 경우(장애학생 국가근로 모집)가 있었다. 그래서 같은 게시판 글끼리는 묶지 않는다.
- 2026-11-13 결과: 71건 중 재게시 6건 (현대모비스 연구장학생 2, 어의장학생 2, 가족장학생 1, 어의·가족장학금 1)
- 틀린 묶음은 `data/reviewed/`에서 고친다. "같은 장학금의 다른 공지"(모집·연장·결과)를 묶는 일은 분류 쪽이다.

## 정하지 않은 것

- 첨부 텍스트 추출(HWP·PDF)은 데모 범위 밖이다. 시간이 남으면 `text_status`를 `ok`로 채운다.
